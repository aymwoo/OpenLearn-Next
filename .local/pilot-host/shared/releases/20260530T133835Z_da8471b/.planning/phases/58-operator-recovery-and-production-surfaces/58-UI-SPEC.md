## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | 查看课堂事件 |
| Empty state heading | 当前没有需要 operator 介入的课堂事件 |
| Empty state body | 当前课堂、插件与异步链路保持可继续状态。若要主动巡检，请进入 Runtime Inspector 或 Async Operator。 |
| Error state | 当前无法加载课堂事件关联真相。请先刷新页面；若仍失败，改从 Runtime Inspector、Async Operator 或插件治理详情继续排查。 |
| Destructive confirmation | suspend：我已确认这会改变当前课堂运行姿态，并写入恢复审计记录；fallback：我已确认这会切换到降级姿态，并影响当前课堂或关联课堂的运行边界。 |

Phase-specific copy rules:
- classroom/session 首屏默认回答“这堂课现在发生了什么”，不用“控制台”“总览仪表盘”类 generic admin 命名。
- degraded honesty 固定三段标签顺序：`仍可信什么 / 已不可信什么` → `影响范围` → `推荐下一步`。
- 轻确认动作 copy 必须写“追加恢复尝试/重新对账/刷新 authoritative truth”，不能写模糊的“立即修复”。
- 高风险动作 copy 必须显式出现“姿态变化”“影响范围”“审计记录”三个词域中的至少两个。

Source notes:
- `58-CONTEXT.md` 已锁定 honesty 三段模板与 risk-tiered confirmation。
- `async-task-operator-surface.tsx`、`plugin-lifecycle-operator-surface.tsx`、`classroom-control-panel.tsx` 已提供现有 tone；Phase 58 统一成 classroom-first operator 口吻。

## Hierarchy & Information Architecture

### Global IA contract

1. **默认入口不是 mega dashboard。** 保留 `Runtime Inspector`、`Async Operator`、`Plugin Governance` 独立 surface。
2. **新的默认心智模型固定为 classroom/session-first。**
3. `Settings Labs` 在没有 classroom deep link 时，第一屏应直接进入 **classroom incident list**，而不是工具目录。
4. teacher classroom shell 保留最小恢复动作；跨对象排障与高风险恢复留在 operator surfaces。

### Classroom incident list contract

- 采用 **stacked incident cards**，禁止 table-heavy 列表。
- 首屏信息顺序：page title → 当前 posture summary → incident cards → tool deep links。
- 首屏 primary focal point 固定为 `当前 posture summary`；若存在 `failed` 或 `blocked` incident，则第一张 incident card 成为 secondary focal point，并承担唯一 accent CTA。
- 每张 incident card 只允许展示：
  - classroom / class 名称
  - 当前 posture（healthy/degraded/failed/blocked）
  - 一句原因或影响摘要
  - `影响范围`
  - `最后更新时间`
  - 1 个主 CTA（`查看课堂事件`）
  - 0-2 个关联 chips（plugin / command / task）
- 首版过滤仅允许：posture、classroom、updatedAt 排序；禁止首屏堆复杂对象筛选器。

### Classroom/session operator surface contract

- 首屏结构固定为：
  1. session identity hero
  2. 3-4 个 summary metrics
  3. degraded honesty card（如有）
  4. problem-first incident cards
  5. related object next-hop cards（runtime / plugin / command / task）
  6. light actions（仅 `retry` / `reconcile`）
- 首屏**不出现** full timeline、attempt history、raw diagnostics。
- `latest command`、`problem tasks`、`plugin posture` 在首屏只允许“状态 + 原因/影响 + 下一跳”。

### Classroom shell escalated CTA contract

- operator 入口稳定可见，但默认是低干扰 secondary affordance。
- 一旦 posture 为 `degraded`、`failed`、`blocked`，该入口升格为更显眼的 incident CTA。
- 升格后保留当前课堂最小恢复按钮，但不在 classroom shell 执行 `resume` / `suspend` / `fallback`。

Source notes:
- 完全来自 `58-CONTEXT.md` 的 D-58-01 ~ D-58-07、D-58-16 ~ D-58-21。

## Alert Posture

| Posture | Visual treatment | Copy posture | Allowed action posture |
|---------|------------------|--------------|------------------------|
| Healthy / watchable | neutral tonal card (`surface-container-lowest`) | 简短状态 + 更新时间 | tertiary / secondary deep link only |
| Degraded but continuing | warm amber honesty card (`#fff7ed`) | 强提示，但先说明仍可信边界 | 允许 `retry` / `reconcile`；保留 detail links |
| Failed / blocked requiring operator | amber hero + stronger accent CTA | 明确“当前课堂受影响”或“平台级受影响” | 首屏仅允许轻确认；高风险动作导向 detail |
| High-risk posture change | rose confirm panel (`#fff1f2`) | 必须写姿态变化、影响范围、审计记录 | 仅 detail confirm 可执行 |

Rules:
- 不使用 1px divider、红色整页告警条、黑底运维控制台风格。
- `degraded` 不是 `destructive`；默认使用暖橙 honesty，而不是 panic red。
- `failed` 也先说 trust boundary，再说失效点；不能只有错误码。

## Degraded Honesty Contract

### Fixed three-part template

1. **仍可信什么 / 已不可信什么**
   - 第一行必须先说 canonical truth 或当前仍可依赖的层。
   - 同一段内紧接着写已不可信的层，不拆到末尾。
2. **影响范围**
   - 必须明确是：当前课堂 / 多课堂 / 平台级。
3. **推荐下一步**
   - 必须给具体目标：`查看 Runtime Inspector`、`查看任务详情`、`进入插件治理详情`、`查看课堂事件`。

### Rendering rules

- 三段顺序不可更改，不可省略任一段。
- 用一张完整 honesty card 呈现，不允许 badge-only、tooltip-only、reason-code-only。
- 卡片标题写 posture 事实，不写泛化标题；示例：`当前仅保证本实例课堂同步`、`当前不能把该课堂视为已完全恢复`。
- 每张 honesty card 最多 1 个 accent CTA；其余为 secondary deep links。

### Canonical copy examples for Phase 58

- **Redis degraded**：`仍可信什么：SQLite canonical truth 仍可读，当前课堂可继续按本实例同步。已不可信什么：跨实例 fanout 不能视为完全健康。` → `影响范围：当前课堂优先，多课堂可能受同类影响。` → `推荐下一步：查看 Runtime Inspector。`
- **Worker lag**：`仍可信什么：任务 ledger 与已完成结果仍可信。已不可信什么：队列处理时效与“刚触发立即生效”的假设不可依赖。` → `影响范围：当前课堂及共享 worker 的关联任务。` → `推荐下一步：查看 Async Operator。`
- **Plugin disabled / incompatible**：`仍可信什么：课堂 session 与已落库 evidence 仍可信。已不可信什么：该插件 action 不能继续按当前版本执行。` → `影响范围：当前课堂及引用同版本插件的课堂。` → `推荐下一步：进入插件治理详情。`

## Action Posture & Confirmation Tiers

| Action | Tier | Placement | Visual style | Copy contract |
|--------|------|-----------|--------------|---------------|
| retry | 轻确认 | classroom/session 首屏 incident card 或 detail summary | secondary button，紧邻原因摘要 | `追加一次恢复尝试，并刷新当前 authoritative truth` |
| reconcile | 轻确认 | classroom/session 首屏 incident card 或 detail summary | secondary button，低于主 drill-down CTA | `重新对账当前状态，不改写历史 truth` |
| resume | 重确认 | detail view only | 先 secondary 入口，再进入 rose confirm panel | `我已确认这会恢复运行姿态，并写入审计记录` |
| suspend | 重确认 | detail view only | rose-toned confirm button，不使用蓝色 gradient | `我已确认这会暂停当前运行姿态，并影响课堂行为` |
| fallback | 重确认 | detail view only | rose-toned confirm button，不使用蓝色 gradient | `我已确认这会切换到降级姿态，并改变当前能力边界` |

Rules:
- `retry` / `reconcile` 是 Phase 58 唯一 quick path。
- `resume` 不是 quick path；与 `suspend`、`fallback` 同级。
- 不可执行动作必须 `disabled + reason + next step`，不能隐藏。
- 高风险确认层必须固定展示：`影响范围`、`姿态变化`、`将写入的审计记录`。
- summary surface 上高风险动作最多出现为 disabled entry 或 detail link，不直接执行。

## Phase 58 Surface Contracts

### 1. Settings Labs / incident-first fallback entry

- 默认承接 recent incidents，而不是工具宫格。
- 顶部 hero 文案强调“跨课堂排障入口”，但视觉仍沿用现有 `Settings Labs` tonal shell。
- `Runtime Inspector`、`Async Operator`、`Plugin Governance` 继续作为 next-hop cards 保留在下方或侧栏。

### 2. Classroom incident list row anatomy

- 左侧：classroom / lesson / posture / 1 句问题摘要。
- 中段：影响范围、关联对象 chips（plugin / command / task，最多 2 个）。
- 右侧：更新时间 + `查看课堂事件`。
- hover 只用 tonal shift / shadow，不加边线。
- 所有 icon-only / compact action 必须带 `tooltip` 与可读文本 fallback，至少提供 `aria-label`；若 action 进入键盘焦点顺序，还需提供 `sr-only` label。

### 3. Classroom/session operator summary cards

- summary metrics 最多 4 张：session state、plugin posture、latest command、problem tasks。
- metrics card 只显示当前状态，不塞 timeline 或 long-form body。
- related object cards 必须都输出稳定 href，禁止只显示 raw IDs。

### 4. Detail surface continuity

- async task detail 继续使用 `summary -> attempts -> timeline`。
- runtime inspector 继续使用 `health -> honesty -> unified timeline`。
- plugin governance 继续使用 `executable actions / diagnostics` split。
- Phase 58 只负责把这些 surface 用 classroom incident relation cards 串起来。
