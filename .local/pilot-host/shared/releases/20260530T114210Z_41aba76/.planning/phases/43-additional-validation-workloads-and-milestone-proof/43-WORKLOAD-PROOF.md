# Phase 43 Workload Proof Matrix

## Milestone proof summary

`v2.3 Async Task Platform` 现在已经不再只是 `course_import.apply_batch` 的单任务通道。Phase 43 通过一个 canonical verifier（`scripts/verify-phase43-validation-workloads.ts`）和下面这份人工可读 coverage matrix，同时证明四个真实 workload family——`batch import`、`reminder delivery`、`classroom session summary`、`resource knowledgeSource ingest`——共享同一套 registry、canonical enqueue seam、worker posture、durable business truth、retry/backoff/idempotency、operator visibility、recovery/result semantics。它们分别覆盖 manual、scheduled、derived 三种 trigger mode，并直接回应 D-43-14、D-43-15、D-43-16 与 ATP-23。

## Requirement alignment

- **D-43-14 / ATP-23:** proof 不再停留在“新增了几个 taskType”，而是把四个 workload family 放进同一张 contract matrix，逐项证明 shared registry、enqueue、worker、operator visibility 与 result semantics。
- **D-43-15:** matrix 明确标注三种 trigger mode：`manual`（batch import）、`scheduled`（reminder delivery）、`derived`（classroom session summary / resource knowledgeSource ingest）。
- **D-43-16:** 每一行都绑定 `business truth`、`enqueue path`、`worker posture`、`retry/backoff/idempotency`、`operator visibility`、`recovery posture`、`result semantics`，而非只说“任务能跑”。

## Anti-regression notes

- **不重开 classroom realtime mainline：** `classroom.session_summary` 只读取 `classroomEvents` 并写 `classroomSessionSummary` derived artifact；不把 worker 变成新的 canonical classroom 写路径。
- **不把 Redis/BullMQ 提升为 business truth：** 所有用户/运营可见状态仍以 SQLite 中的 `asyncTasks`、`asyncTaskEvents`、`scheduleReminderDispatch`、`classroomSessionSummary`、`knowledgeSources`、`knowledgeChunks` 为准，Redis/BullMQ 只做 orchestration/execution substrate。
- **教师页保持 business-entity-first：** `/teacher/schedule/reminders` 与资源中心继续显示业务实体 truth，不暴露 task-center drift；retry / recovery 统一只在 operator 面出现。
