## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: interactive targets must keep a minimum 44px touch height; hero shells may use existing `teacherSurfaceRhythm.hero`/`gradientHeroContent` padding without adding new ad-hoc spacing tokens.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f5f7f9` | Page background, app floor, wide shells |
| Secondary (30%) | `#eef1f3` | Cards, sidebar, nav, section shells |
| Accent (10%) | `#0050d4 → #7b9cff` | Primary CTA, active trend focus, selected metrics only |
| Destructive | `#b31b25` | Destructive actions only |

Accent reserved for: gradient primary CTA, active navigation/current selection, trend anomaly emphasis, selected trend/detail state, recap/trends deep-link CTA. Never use accent for every button, every badge, or every interactive element.

## Phase 26 surface scope

| Surface | Contract |

## Shared product skeleton

| Layer | Contract |
|------|----------|
| Shell | Reuse existing route metadata resolver; `trends` must register as `left-nav`, `rounded`, `default`, `default`. |
| Width | Reuse `surfaceWidths.workspace`, `heroTitle`, `heroBody`; no new page-specific max-width recipes. |
| Rhythm | Reuse `teacherSurfaceRhythm.stack/hero/section/sectionCompact/cardInset`; no one-off shell language. |
| Hero posture | One clear hero per page. Gradient is reserved for the primary stage or primary CTA strip, not repeated as multiple competing heroes. |
| Section posture | Use tonal section shells and white inset cards. No 1px divider lines. Boundaries come from surface shifts, spacing, and shadow-ambient only. |
| CTA grammar | Each page gets one primary CTA maximum. Secondary actions use tonal or text posture. Destructive actions use semantic error tones, never brand blue. |
| State language | Use calm deterministic labels: `上升` / `稳定` / `回落` / `需关注` / `未评价`. Preserve `未评价` as an explicit state. |

## Trends interaction contract

| Topic | Contract |
|------|----------|
| Entry posture | Default landing is class-first, not student-first. |
| Time window | Default view compares the latest 4 ended classroom sessions; if fewer than 4 exist, show all available sessions. |
| Comparison unit | Default unit is real recent sessions, not lesson aggregate. Lesson aggregate may exist only as a secondary toggle. |
| Drill-down | Clicking an anomaly opens inline detail on the same trends page first. Never hard-jump immediately away. |
| Inline detail contents | Must show session summary, impacted students, key signals, and the next recommended action. |
| Primary next step | Primary CTA from trends detail goes to `/classroom?sessionId={id}&recapTab=students`. |
| Secondary next step | Secondary CTA may go to `/teacher/review` only for feedback follow-up after session context is understood. |
| Student trends | Student-level trends live as drill-down, focus list, or secondary panel under the class trend narrative. |

---

## Trend visualization contract

| Element | Contract |
|--------|----------|
| Primary comparison | Use compact line, bar, sparkline, or session-card delta views that answer “这个班最近几次课发生了什么变化”. |
| Status emphasis | Emphasize deltas with tone and short labels, not dense dashboards. |
| Raw evidence bridge | Every anomaly block must expose the exact session pointer and affected student subset. |
| Charts to avoid | No pie chart as the primary trend view. No decorative-only chart background. No AI-generated narrative summary blocks. |
| Density | Desktop may use 60/40 split for comparison + detail. Mobile must collapse into stacked cards with inline expansion below the tapped summary. |

---

## Responsive contract

| Breakpoint | Contract |
|-----------|----------|
| Mobile | Single-column flow; hero first, summary metrics second, comparison cards third, expanded detail inline below the selected item. |
| Tablet | Two-column secondary sections are allowed, but anomaly detail still stays in-page. |
| Desktop | Main comparison area + contextual detail rail may use a stable 60/40 or 50/50 split depending on page task, reusing existing route posture. |
| All sizes | No horizontal scroll for analytics cards. Long explanatory copy must wrap within `heroBody`/section width contracts. |
