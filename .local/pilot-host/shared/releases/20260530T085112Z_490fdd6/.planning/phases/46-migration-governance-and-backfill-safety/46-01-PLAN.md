# Phase 46-01 PLAN: Migration Governance & Backfill Safety

## 1. 计划目标 (Objectives)
* 确立 Drizzle schema 的绝对权威，确保任何插件生命周期行为（install/reconcile）在运行时均只操作 DML，不发起任何 DDL 建表/改表动作。
* 实现支持 JSON -> 物理扩展表数据平滑割接的服务 `src/lib/dal/plugin-migration.ts`，内置 **Backfill (回填)**、**Verify (核对)** 与 **Cutover (割接)** 三阶段原子流程，消除双重真相分裂。
* 编写完善的单元与集成测试 `src/lib/dal/plugin-migration.test.ts` 论证割接的原子性、幂等性与零损耗。
* 开发高韧性静态前缀命名空间拦截器，并建立一键闭环的 `verify:phase46` close gate，向前级联回归。

---

## 2. 核心割接服务设计 (Migration Service Design)
我们在 `src/lib/dal/plugin-migration.ts` 中开发：

```typescript
export interface MigrationResult {
  processed: number;
  succeeded: number;
  failed: number;
  errors: Array<{ entityId: string; reason: string }>;
}

/**
 * 1. Backfill 阶段：读取 core entity 的 payloadJson 并解析指定 pluginId/pluginKey 的配置，
 * 幂等写入至 plugin_ext_ 表中
 */
export async function backfillPluginJsonToSchema(
  actorId: string,
  schoolId: string,
  pluginId: string,
  entityType: "lesson" | "step" | "resource"
): Promise<MigrationResult>;

/**
 * 2. Verify 阶段：对比核心实体 JSON 与新物理扩展表中的 payloadJson 是否完全一致
 */
export async function verifyBackfillData(
  actorId: string,
  schoolId: string,
  pluginId: string,
  entityType: "lesson" | "step" | "resource"
): Promise<{ matches: boolean; mismatches: string[] }>;

/**
 * 3. Cutover 阶段：擦除核心实体 payloadJson 中该插件相关的特征字段，以后完全收口于物理扩展表
 */
export async function cutoverPluginJsonToSchema(
  actorId: string,
  schoolId: string,
  pluginId: string,
  entityType: "lesson" | "step" | "resource"
): Promise<MigrationResult>;
```

### 数据搬运细节：
- 比如针对 `lesson` 实体，如果在 `lessons.payloadJson`（注：我们之前是存储在 `lessons` 行上）包含 `"{ reminders: { ... } }"`。
- 我们将解析 `reminders` 的配置属性，将其提取出来，作为独立的 payload 写入物理表 `plugin_ext_lesson` 中。
- 割接完成后，原 `lessons.payloadJson` 将不再有 `reminders` 键（其它非该插件所有的零碎配置仍妥善保留），实现彻底的单真相收口。

## 3. 命名规范静态校验 (Static Naming Checks)
在校验脚本中利用正则表达式或 AST 读取 `src/db/schema.ts` 定义：
- 所有表定义（`sqliteTable("name", ...)`）若不属于核心表，则其物理表名必须强制以 `plugin_ext_` 或 `plugin_owned_` 开头。
- 所有非核心表的索引定义（`uniqueIndex("name")` 或 `index("name")`）其物理索引名必须强制以 `plugin_ext_` 或 `plugin_owned_` 开头。
- 否则，本地校验命令执行失败，阻止构建。

## 4. 自动化测试与验证 (Validation Strategy)
* 测试文件：`src/lib/dal/plugin-migration.test.ts`
* 验证用例：
  - **Backfill 数据同步**：模拟旧 lesson payloadJson 中含有 `'reminders'` 插件数据，执行 backfill 后，`plugin_ext_lesson` 成功捕获并完美落库。
  - **Verify 精准对比**：校验对比一致性。人为篡改物理扩展表 payload，Verify 判定不一致并抛错。
  - **Cutover 事务割接**：在同一事务中删除旧 JSON 的 plugin key 并更新 lessons，数据无损，且 core 层的 JSON 中完全擦除了 reminders 项。
  - **DML Only 运行时断言**：模拟 reconcile 过程，断言执行完后物理库表未受 DDL 操作，100% 保持静态权威。
* 执行指令：
  ```bash
  pnpm exec vitest --run src/lib/dal/plugin-migration.test.ts
  pnpm run verify:phase46
  ```
