<objective>
修复教师测试账号 POST `/login` 成功后进入 `/teacher/editor` 仍触发
`TEACHER_AUTH_REQUIRED` 的问题。

没有写入 `assertActiveTeacher()` 要求的 active teacher membership。此计划要求
一次性闭合登录 session、teacher membership、redirect、proxy 与 DAL 读路径。

Output: Auth.js JWT/session callback 修复、测试教师账号完整 seed、以及 Phase 3
authoring 回归检查。

```typescript
export async function getCurrentUserDTO(): Promise<UserDTO | null> {
  const session = await auth();
  if (!session?.user?.id) return null;
  const userRecord = await db.query.users.findFirst({ where: eq(users.id, session.user.id) });
  return userRecord ? UserDTOSchema.safeParse(userRecord).data : null;
}
```

From src/lib/dal/lesson-authoring.ts:
```typescript
export async function assertActiveTeacher(): Promise<TeacherScope> {
  const user = await getCurrentUserDTO();
  if (!user) throw new Error("TEACHER_AUTH_REQUIRED");
  const memberships = await getUserMembershipsDTO(user.id);
  const schoolIds = memberships
    .filter((membership) => membership.role === "teacher" && membership.status === "active")
    .map((membership) => membership.schoolId);
  if (schoolIds.length === 0) throw new Error("TEACHER_AUTH_REQUIRED");
  return { userId: user.id, schoolIds };
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser login form → Server Action | 用户可控 credentials 进入 `signInAction`。 |
| Server Action → Auth.js CredentialsProvider | Node-backed Auth.js 校验密码并生成 JWT session。 |
| Auth.js session → DAL | `auth()` 产出的 `session.user.id` 被 `getCurrentUserDTO()` 用于 DB 查询。 |
| Seed script → SQLite auth/authorization tables | 本地开发脚本写入测试用户、学校、membership。 |
| Proxy → authConfig | 受保护 teacher route 只使用 edge-safe config 判断是否登录。 |
