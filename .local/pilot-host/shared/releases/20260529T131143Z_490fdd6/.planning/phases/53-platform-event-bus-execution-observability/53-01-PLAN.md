<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| command handler result → event contract | handler-owned facts cross into durable event truth and must be validated before persistence |
| platform event ledger → command summary | invalidation/failure attribution must stay summary-only and not become a second object store |
| platform event modules → runtime transport modules | accidental reuse of runtime outbox/bus would invert locked truth ownership |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-53-01 | T | `events/contracts.ts` | mitigate | Validate all emitted events with Zod and restrict domain events to handler-owned typed schemas per D-53-07. |
| T-53-02 | T/R | `src/db/schema.ts` event tables | mitigate | Use dedicated `platformEvents` + `platformEventDispatches` tables keyed by `commandId`/`attemptNumber`; never store event truth in command summary JSON. |
| T-53-03 | I | payload summary fields | mitigate | Keep summary-only payloads and reject full object snapshots per D-53-03. |
| T-53-04 | T/E | runtime/platform seam | mitigate | Add static/test guard that platform event modules do not import `runtimeEventOutbox` or runtime bus adapters per D-53-10. |
</threat_model>
