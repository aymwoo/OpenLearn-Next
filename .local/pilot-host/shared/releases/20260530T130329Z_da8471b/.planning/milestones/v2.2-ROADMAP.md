## ROADMAP

**Milestone:** v2.2 WebSocket Classroom Transport Cutover
**Archived:** 2026-05-18
**Status:** ✅ SHIPPED
**Closure scope:** Phase 36-38 only
**Total plans:** 9

## Overview

本 milestone 把课堂实时链路从 SSE-only 交付面收口为 `ws` 正式交付路径，并补齐了 optional `ioredis`
fanout、operator-visible degraded posture、repo-local demo/bootstrap 文档，以及单一 milestone close gate。

成功线不是“把更多 runtime backlog 一起做完”，而是把 `ws + ioredis` classroom transport 变成单一、可验证、可演示、可归档的交付面，同时继续把 SQLite + DAL + canonical classroom/runtime write path 保持为 durable truth。

## Phases

### Phase 36: WebSocket classroom transport cutover

**Goal**: 在现有 transport gateway 和课堂 durability truth 之上，完成课堂与 runtime 的正式 WebSocket 双向通信切换，并固定技术选型为 `ws`。
**Depends on**: Phase 31, Phase 33, Phase 35
**Plans**: 4 plans

Plans:

- [x] 36-01-PLAN.md — Define the `ws` handshake, message envelope, connection registry, and session-scoped route cutover boundary.
- [x] 36-02-PLAN.md — Repair the backend cutover path: real handshake auth, actor-aware snapshot reads, enum convergence, and canonical routing for inbound websocket commands.
- [x] 36-03-PLAN.md — Wire classroom, player, and runtime-host consumers onto the unified websocket contract while preserving SSE rollback and durable snapshot parity.
- [x] 36-04-PLAN.md — Add focused verification for websocket route auth, message validation, canonical routing, and classroom parity against the current SSE behavior.

**Details:**

- 建立了真实鉴权的 WebSocket handshake、typed envelope、Node upgrade host 与 session-scoped connection registry。
- teacher `/classroom`、student runtime/player 与 runtime host 已切到 WS-first posture，但仍保留 SSE rollback surface 与 durable snapshot correction。
- `verify:phase36` 成为 WebSocket cutover 的 canonical phase gate。

### Phase 37: Redis fanout and multi-instance delivery convergence

**Goal**: 用 `ioredis` 把新的 WebSocket transport 升级为可多实例分发的课堂 fanout 基础设施，同时保持 Redis 只是 delivery 层，不是业务真相源。
**Depends on**: Phase 36
**Plans**: 3 plans

Plans:

- [x] 37-01-PLAN.md — Add the `ioredis` adapter, connection factory, and session-scoped publish/subscribe contract for classroom transport.
- [x] 37-02-PLAN.md — Converge runtime/classroom fanout, reconnection, and cross-instance delivery semantics on the Redis-backed adapter.
- [x] 37-03-PLAN.md — Add Redis health, local bootstrap expectations, and focused failure-recovery verification for the new delivery path.

**Details:**

- 新增 deploy-authoritative transport setting、session transport snapshot 与 Redis fanout seam。
- Redis degraded 时会诚实暴露 local-only fallback 和 cross-instance failure，不再把退化路径伪装成透明成功。
- `/settings`、runtime inspector、teacher `/classroom` 已具备 operator-visible transport posture。
- `verify:phase37` 把 Redis fanout、recovery、local bootstrap 和 degraded honesty 收口为 phase gate。

### Phase 38: Cutover verification, fallback, and operational hardening

**Goal**: 把 `ws + ioredis` cutover 收口为单一可验证交付面，包括 fallback posture、观测性、开发/验收路径和 milestone close artifact。
**Depends on**: Phase 37
**Plans**: 2 plans

Plans:

- [x] 38-01-PLAN.md — Publish the canonical cutover verifier and route-by-route parity proof for classroom, player, and runtime flows.
- [x] 38-02-PLAN.md — Document fallback, bootstrap, observability, and milestone close posture for the new transport stack.

**Details:**

- `verify:phase38` 成为唯一外部 milestone close gate，并组合 `verify:phase36` 与 `verify:phase37`。
- `38-VERIFICATION.md`、`38-FALLBACK-MATRIX.md`、`38-DEMO-RUNBOOK.md`、`38-CLOSEOUT.md` 已把 parity proof、fallback posture、demo/bootstrap 与 close wording 固化为 repo-local artifact。
- close 结论明确限定在 `ws + ioredis` classroom transport，不把 PostgreSQL、BullMQ、Redis Streams、第二 runtime、第三方 runtime 或 AI runtime expansion 混入本次完成口径。

## Milestone Summary

**Decimal Phases:** none

**Key Decisions:**

- 使用 `ws` 作为正式 classroom transport delivery path，并通过 authenticated envelope + session-scoped registry 收口握手与消息语义。
- Redis fanout 保持 optional、deploy-authoritative、delivery-only posture，不让 Redis 或 WebSocket 反客为主成为 durable truth source。
- 把 `verify:phase38` 固定为唯一外部 milestone close gate，而不是继续依赖人工拼接多个 verifier 或口头 close 解释。

**Issues Resolved:**

- 结束了课堂实时链路对 SSE-only delivery posture 的依赖。
- 让 Redis degraded/local-only posture 对 operator 变得显式可见。
- 让 cutover close 结论具备 repo-local proof chain、fallback matrix 与 demo runbook，而不是继续依赖作者记忆。

**Issues Deferred:**

- close 时不存在 `v2.2` milestone audit 文件；该风险已在 close 时显式接受。
- `RTPX-01` PostgreSQL cutover、broader `RTPX-02` async worker/BullMQ slice、`RTPX-04`、`RTPX-05`、`RTPX-06` 继续 deferred。

**Technical Debt Incurred:**

- Redis smoke path 仍依赖显式环境变量与本地 bootstrap，不是默认开发基线。
- broader async-worker / fanout orchestration 仍未进入本 milestone 的已完成范围。
