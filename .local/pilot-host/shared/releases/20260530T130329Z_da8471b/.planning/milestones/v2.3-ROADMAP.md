## ROADMAP

**Milestone:** v2.3 Async Task Platform
**Archived:** 2026-05-20
**Status:** ✅ ARCHIVED WITH ACCEPTED GAPS
**Closure scope:** Phase 39-43 only
**Total plans:** 16

## Overview

`v2.3` 把仓库从“只有同步请求语义”推进到一个真实可复用的 Async Task Platform：typed task registry、统一 enqueue boundary、SQLite durable task ledger、BullMQ worker、QueueEvents projection、operator visibility 和 safe retry posture 都已经落地。

成功线不是再做一轮 infra rewrite，而是在不重开 classroom realtime mainline、不过早绑定 PostgreSQL 或 AI runtime 的前提下，让真实教育任务通过同一套 durable truth、worker posture、status/read model 和 operator recovery 跑通。

本 milestone 在 close 时接受了已知 gaps：`ATP-22` 仍缺 teacher `/resources` 产品触发入口，`ATP-23` 因第四类 workload 缺少真实产品闭环只算 partial，且 Phase 39-41 proof chain 仍有 verification artifact 缺口。

## Phases

### Phase 39: Async contracts and durable task truth

**Goal**: 建立 `src/features/async-tasks` 基础 root、typed task registry、统一 enqueue contract 和 SQLite task ledger，让平台先拥有稳定 truth 与 DTO/read model。
**Depends on**: Phase 38
**Plans**: 3 plans

Plans:

- [x] 39-01-PLAN.md - Add the `src/features/async-tasks` feature root, typed task registry, and shared Zod contracts.
- [x] 39-02-PLAN.md - Add the SQLite async task ledger schema, event history tables, and DAL read models for task DTOs.
- [x] 39-03-PLAN.md - Add the application enqueue boundary and intent recording so server actions enqueue through one platform seam.

**Details:**

- 建立了 typed async task registry、shared payload/progress/result contracts 与统一 feature root。
- durable async task truth 落在 SQLite ledger、event history 和 DAL DTO/read model，而不是 BullMQ state。
- 所有后续 workload 都复用同一个 `enqueueAsyncTask()` 平台边界。

### Phase 40: BullMQ infra seam and worker reliability posture

**Goal**: 在不改业务主链路的前提下跑通 enqueue -> worker pickup -> QueueEvents projection -> durable status update 的平台闭环，并把 retry、幂等、恢复语义固定下来。
**Depends on**: Phase 39
**Plans**: 3 plans

Plans:

- [x] 40-01-PLAN.md - Add BullMQ connection factories, queue and worker bootstrap, and dedicated worker entry scripts.
- [x] 40-02-PLAN.md - Add QueueEvents projection, failure and attempt history recording, stalled recovery, and graceful shutdown posture.
- [x] 40-03-PLAN.md - Add retry, backoff, idempotency, and execution helpers plus a minimal platform verification task.

**Details:**

- worker 被固定为独立进程入口，Redis/BullMQ 只承担 orchestration 与 execution substrate。
- QueueEvents 会把 queued、running、retrying、completed、failed 等 runtime state 投影回 SQLite durable truth。
- retry/backoff、idempotency、graceful shutdown 与 stalled recovery posture 被统一收口到平台层，而不是散落在单个业务 job 里。

**Goal**: 用 batch import 这条用户价值高、状态最容易解释的真实链路验证平台不是纯 infra，而是真正可被 teacher/staff 使用的异步产品能力。
**Depends on**: Phase 40
**Plans**: 3 plans

Plans:

- [x] 41-01-PLAN.md - Integrate batch import onto the async task registry, active-task dedupe, enqueue path, and worker processor model.
- [x] 41-02-PLAN.md - Add teacher/staff status surfaces on the batch detail truth page and the course-center recent-task card.

- active batch dedupe、typed result summary 和 cache-safe updates 把“异步执行”变成真实产品能力，而不是后台日志技巧。

**Depends on**: Phase 41
**Plans**: 3 plans

Plans:

- [x] 42-02-PLAN.md - Add per-task run detail surfaces with attempt history, progress snapshots, and latest error DTOs.
- [x] 42-03-PLAN.md - Add safe operator retry actions, audit posture, and focused recovery verification.

- operator 可查看 run detail、attempt history、progress snapshots 与 latest failure，而不需要直接看 BullMQ admin state。

## Milestone Summary

**Decimal Phases:** none

**Key Decisions:**

- v2.3 Async Task Platform 采用 BullMQ + 独立 worker 进程 + SQLite task ledger，保持 Redis/BullMQ 不成为业务真相源。
- 产品面继续坚持 business-entity-first posture，让 async truth 通过 DTO 映射回 batch/reminder/resource surface，而不是单独造 task center。
- operator recovery 只暴露给 operator role，并通过 typed recovery action + audit posture 收口，而不是允许人工 patch 数据。

**Issues Resolved:**

- 结束了长任务只能依赖同步请求或 ad hoc queue call 的状态。
- 让 teacher/staff 可以看到 honest queued/running/completed/failed/partial posture，而不是把 queued 伪装成 done。
- 让 operator 可以从产品面查看健康、错误、历史并安全重试，而不是只在 worker 日志里盯 job id。

**Issues Deferred:**

- `ATP-22`: `resource.knowledge_source_ingest` 仍缺 teacher `/resources` 产品触发入口。
- `ATP-23`: 第四类 workload 因产品触发闭环未完成，只能算 partial proof。
- Phase 39 / 40 / 41 proof chain 仍缺 `39-VERIFICATION.md`、`40-VERIFICATION.md`、`41-VERIFICATION.md`，且 `package.json` 未注册 `verify:phase40`。
- `classroom.session_summary` artifact 已落库，但 `/classroom` 页面仍未消费该 artifact 读路径。

**Technical Debt Incurred:**

- `scripts/verify-phase43-validation-workloads.ts` 的 canonical gate 覆盖面仍偏窄，需要额外 focused suite 补跑。
- `src/lib/dal/classroom.ts` failed summary artifact 仍使用 `lessonId: "unknown"` / `classId: "unknown"` 占位值。
- `verify:phase42` 与 `verify:phase40` 的 npm entry posture 仍不一致。
