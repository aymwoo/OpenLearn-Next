# Phase quick Plan 1: Settings manifest theme Summary

修复了开发环境主题数据无法补种的问题。设置页显示“当前学校还没有可用主题”并不是读取逻辑出错，而是 `pnpm db:bootstrap:dev` 在执行 `scripts/bootstrap-dev-db.ts` 时，因为直接 import 了带 `server-only` 的 `src/lib/dal/themes.ts` 而崩溃，导致本地库里根本没有 `星夜课堂主题` 数据。

## Completed Tasks

1. **Task 1: 让开发 bootstrap 可复用主题注册逻辑而不触发 `server-only` 崩溃** (Commit: `304ce1b`)
   - 新增 `src/server/themes/registry.ts`，承接 `registerThemeTokens()` 和 `recordThemeAudit()` 的共享实现。
   - 让 `src/lib/dal/themes.ts` 仅保留 `server-only` 边界与查询函数，并继续 re-export 主题注册 API 给现有调用方使用。
   - 把 `scripts/bootstrap-dev-db.ts` 改为直接从 `@/server/themes/registry` 引入主题注册逻辑，避免 `tsx` 执行脚本时报错。

2. **Task 2: 验证开发库已真正产生学校范围主题数据** (Commit: `304ce1b`)
   - 更新 `scripts/bootstrap-dev-db.test.ts`，使测试跟随新的共享 helper 结构，而不是继续假设幂等逻辑仍写在 DAL 文件里。
   - 重新执行 `pnpm db:bootstrap:dev`，确认输出包含“可用主题：星夜课堂主题”。
   - 验证 `local.db` 中存在启用状态的 `星夜课堂` 插件和 `validationStatus = valid` 的 `星夜课堂主题` 记录。

## Verification

1. `pnpm db:bootstrap:dev`
2. `pnpm vitest run scripts/bootstrap-dev-db.test.ts src/components/surfaces/settings-surface.test.tsx src/actions/theme-actions.test.ts src/lib/dal/themes.test.ts src/lib/dal/plugins.test.ts`
3. `sqlite3 local.db "select id,schoolId,name,enabled,killSwitchEnabled from pluginRegistration where name='星夜课堂';"`
4. `sqlite3 local.db "select id,schoolId,name,validationStatus from themeTokenRegistry where name='星夜课堂主题';"`

## Deviations from Plan

### Resolved during execution

**1. 原计划假设问题在 settings 读取过滤层，但实际根因在 bootstrap 执行链路**
- **Found during:** live reproduction with `pnpm db:bootstrap:dev`
- **Issue:** 开发脚本在执行时直接命中 `server-only` runtime guard，导致主题种子从未写入本地数据库。
- **Fix:** 将可复用的主题注册实现提取到 `src/server/themes/registry.ts`，让脚本与 DAL 共用同一实现。
- **Files modified:** `src/server/themes/registry.ts`, `src/lib/dal/themes.ts`, `scripts/bootstrap-dev-db.ts`, `scripts/bootstrap-dev-db.test.ts`
