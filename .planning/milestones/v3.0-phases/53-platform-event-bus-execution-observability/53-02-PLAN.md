<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| handler result → command bus | explicit event facts supplied by handlers must not be altered or auto-inferred by the bus |
| command bus → event ledger | success/failure persistence must remain atomic enough to preserve command/event traceability |
| failure path → domain event families | failed commands can leak false business facts if domain events are appended on error |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-53-05 | T | `handlers/plugins.ts` | mitigate | Make handlers explicitly return domain events and reject DAL-generated or bus-inferred event semantics per D-53-07. |
| T-53-06 | R | `commands/bus.ts` append flow | mitigate | Persist command summary and event rows with shared `commandId`/`attemptNumber`/correlation metadata before notification. |
| T-53-07 | T/I | failure event handling | mitigate | On failure append exactly one generic failure event and zero domain events per D-53-04/D-53-08. |
| T-53-08 | E | cache invalidation ownership | mitigate | Keep invalidation intent on the command result/summary and never execute cache APIs inside the bus per D-53-14. |
</threat_model>
