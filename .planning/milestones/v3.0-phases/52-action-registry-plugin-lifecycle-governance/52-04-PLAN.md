<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| uninstall UI intent -> command payload | cleanup 是破坏性操作，必须把显式确认带到服务端而不是只停留在客户端状态 |
| host recovery adapter -> lifecycle mutation path | host 入口会对 blocked 插件发恢复命令，必须精确限制允许的恢复动作 |
| dependency helper -> lifecycle transitions | 依赖顺序从 read model 进入写路径后，任何错误判断都会导致半激活状态 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-52-04-01 | T | `plugin.uninstall` payload | mitigate | 用 deterministic confirmationToken + server-side preflight recheck 防止 cleanup 被伪造。 |
| T-52-04-02 | I | retain uninstall row | mitigate | retain 分支保留 registration row 并投影为 `uninstalled`，避免把历史与扩展数据误删。 |
| T-52-04-03 | E | `plugin-host.ts` recovery gate | mitigate | 仅放行与 `reasonCode` 匹配的恢复命令，dependency 问题仍需显式 reconcile。 |
| T-52-04-04 | D | dependency activation ordering | mitigate | 在写路径前先解析 chain；一旦 missing/cycle/failure，整条受影响链路 fail-fast，避免半启动。 |
</threat_model>
