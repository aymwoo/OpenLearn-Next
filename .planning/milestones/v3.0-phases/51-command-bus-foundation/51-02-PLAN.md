<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| command handler → plugin DAL | authorization or lifecycle rules can drift if handlers bypass canonical DAL helpers |
| retry request → existing command row | replay path can create duplicate side effects if it seeds a new business command |
| command context → plugin audits | missing linkage weakens operator attribution and repudiation defenses |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-51-05 | E/T | `handlers/plugins.ts` bypassing DAL | mitigate | Route all business mutations through tx-aware helpers in `src/lib/dal/plugins.ts`; forbid ad-hoc direct Drizzle mutation logic in handlers. |
| T-51-06 | R | `plugin.retry` | mitigate | Load the existing failed command row and append a new attempt number on the same command id per D-05. |
| T-51-07 | S/E | authorize callbacks | mitigate | Reuse teacher-manager scope and school-scope assertions from existing DAL/host guard patterns before any execute step. |
| T-51-08 | R | audit linkage | mitigate | Persist `commandId` and `correlationId` into plugin/governance audits whenever handlers write those records. |
</threat_model>
