# Milestone v4.1: Multi-Question Types & Teacher Live Dashboard

**Status:** ✅ SHIPPED 2026-06-09
**Phases:** 73-74
**Total Plans:** 7

## Overview

v4.1 extends the v4.0 single-choice quiz sample (`pluginKey = "quiz"`) and the v2.2 classroom WebSocket-first transport to deliver **(a)** a multi-type interactive answer data model (single/multi/true_false/fill_blank/ordering) that flows end-to-end through the same governed verbs (insert/upsert/getByIndex/count/aggregate) and same append-only/`isLatest` response schema used in v4.0, with post-class recap stats per questionType; and **(b)** a **teacher-only, read-only** live answer-flow dashboard tab inside the existing `/classroom` control room, fed by a new `quiz.answer.received` event published on the existing v2.2 `classroom-ws` transport (no new WS endpoint, no second source of truth — SQLite + DAL remain the durable truth, Redis fanout is delivery-only). v4.1 explicitly does **not** redefine the marketplace, governance, or data-access verbs.

## Phases

### Phase 73: Multi-Type Quiz Schema, Live WS Event & Teacher Live Dashboard

**Goal:** 把 v4.0 `quiz` 样板的题型从「单选」扩到 5 种（`single_choice` / `multi_choice` / `true_false` / `fill_blank` / `ordering`），题型可经 D-72.1-04 append-only/`isLatest` 写入插件自有表，并把学生作答事件经 v2.2 `classroom-ws` 通路以 `quiz.answer.received` 推送到教师端 `/classroom` 控制室的一个新增「作答实时」tab。

**Plans:** 2

- [x] **73-01** — Multi-type quiz data model + DAL + student submit + post-class stats
- [x] **73-02** — WS event wiring + teacher live dashboard tab + read-only posture

**Details:**
- 10 sub-IDs covered: QUIZ-EXT-01-A..E + QUIZ-EXT-02-A..E
- Schema migration: `plugin_owned_quiz_questions.questionType TEXT NOT NULL` (additive)
- Data model: 5-enum `QuestionTypeSchema`, DTO payload union, allowlist sync
- DAL: 5 verbs × 5 question types = 25 test cases
- Student submit: append-only/isLatest across all 5 types
- Post-class stats: discriminated union (countByOption/countByOptionSet/countByBool/topAnswers/topOrderings)
- WS event: `quiz.answer.received`, teacher-only channel, v2.2 envelope contract
- Redis fanout: optional, env-driven (REDIS_URL), contract test dual-branch
- Dashboard tab: `/classroom` sibling tab, URL-based tab state, access control
- Live view: Zustand client aggregation, recent N stream + per-question distribution
- Zero-write guard: grep static assertion on dashboard surface
