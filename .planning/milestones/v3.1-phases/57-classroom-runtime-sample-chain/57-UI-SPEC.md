Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline icon gap, badge icon padding delta |
| sm | 8px | Compact status chips, inline metric spacing |
| md | 16px | Default card content gap, body copy stack |
| lg | 24px | Section padding inside runtime cards |
| xl | 32px | Main shell panel gap, aggregate/result split |

| 3xl | 64px | Page-level breathing room only |

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f5f7f9` | App background, classroom shell backdrop, runtime page base |
| Secondary (30%) | `#eef1f3` | Teacher control cards, roster panels, waiting/status containers |
| Accent (10%) | `#0050d4` | Launch CTA, `开始本轮投票`, active step marker, live aggregate emphasis, focus-visible outline |
| Destructive | `#b31b25` | True launch blockers, late-submit rejection, irreversible end-of-round/end-of-class confirmations only |

Accent reserved for: `开启新课堂`, `开始本轮投票`, active current-step badge, live aggregate leader bar/selected result chip, teacher-forced focus state, reconnect recovery CTA, focus-visible outline. Never use accent for every clickable label, generic card borders, or full-panel backgrounds.

Warm warning tone for degraded-but-nonblocking runtime posture: use existing amber/orange family already present in classroom surfaces; it must stay inside tonal cards and never look like a destructive error.

## Surface Contract — Classroom Launch Panel

### 1. Launch gating posture

- Only `blockingIssues` disable `开启新课堂`.
- `attentionIssues` and `advisoryIssues` remain visible in the same panel stack and must never trigger a second confirmation modal.
- If there are zero blockers and at least one attention issue, the CTA remains enabled and the teacher sees the warning inline before launch.

### 2. Issue presentation rule

Each launch issue row must include, when available:
- step title or `step:{id}`
- plugin context / voting context
- human-readable reason

Do not collapse issues into a classroom-level generic summary.

### 3. Visual hierarchy

- Keep the current left form + right readiness split.
- `阻断项` uses destructive chips only at badge/icon level, not full red panels.
- `需关注` uses warm tonal cards.
- `建议完善` uses neutral tonal cards.
- All issue groups remain rounded tonal containers with no separator lines.

### 4. CTA contract

- Primary launch CTA stays a gradient button.
- Minimum height: 52px desktop, 48px compact.
- Disabled only when lesson/class is unselected or blockers exist.
- Pending label: `正在创建课堂，请稍候。`

### 5. Post-launch honesty rule

Once a session is created, subsequent degraded posture must never redirect back into launch preparation language. The classroom must open and carry warnings inside the classroom shell.

## Surface Contract — Classroom Console Surface

### 1. Shell continuity

- Keep the existing gradient hero + tonal secondary panel structure.
- Do not create a new voting route.
- Voting controls and results live inside the current classroom shell under `课堂控制与干预记录`.

### 2. Information priority

Teacher visual order inside the classroom shell:
1. current classroom status and current step
2. voting round control
3. live aggregate result summary
4. incomplete roster
5. folded named detail
6. existing timeline / student detail / session history

### 3. Degraded runtime banner

- Render degraded posture as an in-class warm warning card inside the shell.
- Wording must explain continuity first, limitation second: the class continues, but cross-instance or transport ability is reduced.
- This banner must never visually compete with destructive errors or session-ending controls.

## Surface Contract — Classroom Control Panel

### 1. Voting round control placement

- Place `开始本轮投票` and `结束本轮投票` in the existing teacher control area, not in utility or timeline panels.
- These controls sit at the same command tier as step focus / lock mode because voting is a classroom control action.

### 2. Button semantics

- `开始本轮投票` = primary gradient CTA when round is idle.
- `结束本轮投票` = secondary tonal button with irreversible-warning copy nearby; do not style as full destructive unless ending the round is the only available next action.
- While a command is pending, disable both round controls and retain local layout stability.

### 3. Result panel layout

For an active voting round, the first screen must show three stacked zones in this order:
1. `实时汇总` — answer distribution, submitted count, remaining count
2. `未完成名单` — explicit roster of students without valid latest submission
3. `实名结果` — folded by default, expandable on demand

Do not render实名结果 ahead of aggregate and incomplete roster.

### 4. Aggregate presentation

- Use cards/bars/chips, not a bordered table.
- Each option row shows label, current count, current percentage.
- Leading option may use accent fill; other options use secondary tonal fills.
- Percentages and counts must update during the live round and freeze immediately after teacher end.

### 5. Incomplete roster presentation

- Render as a dedicated block, not as a footnote under aggregate.
- Each row shows student name + minimal current status token only (`未提交`, `离线`, `重新连接中`).
- Keep rows compact, tonal, and scan-friendly.
- If everyone submitted, replace the list with a positive empty state: `全班已提交，可由老师决定何时结束本轮投票。`

### 6. Named detail fold rule

- Default collapsed.
- Expanded state reveals per-student latest valid choice and latest submit time.
- Keep detail in tonal rows or accordion items; no raw log/event presentation.

### 7. Freeze rule after teacher end

- Once the teacher ends the round, aggregate numbers stop live animation and become a frozen result snapshot.
- Show explicit state chip: `本轮已结束`.
- Replace action emphasis from submit-in-progress to result review.

### 8. Failure consequence visibility

- If runtime submit failures exist, surface them in the same result area as a count-backed teacher message, not only in inspector links.
- Use honest copy such as `有 2 名学生提交失败或状态异常，请先查看未完成名单。`

## Surface Contract — Student Runtime Client

### 1. Forced focus rule

- When the teacher starts a voting round, the student runtime must move focus to the current voting step inside the existing player shell.
- Keep the left rail and main stage layout; do not open a separate voting-only full-screen page.

### 2. Submission-success state

- After successful submit, the student remains on the same voting step.
- Replace the primary submit-ready emphasis with a submitted-waiting state card.
- Canonical waiting copy: `已提交，等待老师结束本轮投票`.
- Do not auto-advance, auto-close, or auto-switch to results.

### 3. Same-round overwrite rule

- Before teacher end, student may submit a changed answer again.
- UI must describe this gently: `老师结束前，你可以更新本次选择。`
- If the exact same payload is resubmitted, keep the UI stable and do not show it as a new recorded attempt.

### 4. Late submit rejection

- After teacher end, disable voting inputs and submit CTA.
- Show an inline locked result/warning card: `本轮投票已结束，无法再提交。`
- Never silently swallow the action.

### 5. Reconnect recovery

- On reconnect, restore the current voting step and the student's submitted/not-submitted state.
- If already submitted and round still open, restore the waiting state, not an empty form.
- Keep reconnect messaging inside the existing status banner area.

### 6. Visual posture

- Student shell remains low-distraction and stage-first.
- Use one clear status banner at a time: connection recovery, submitted-waiting, or round-ended locked state.
- Do not stack multiple competing banners above the stage.

## Component State Matrix

| State | Trigger | UI response |
|-------|---------|-------------|
| Launch blocked | one or more `blockingIssues` | disable launch CTA, show step-scoped blocker rows |
| Launch warned | attention/advisory only | keep CTA enabled, show inline warning copy, no confirm modal |
| Voting idle | classroom live but round not started | teacher sees empty aggregate state; student sees normal current-step shell |
| Voting live | teacher started round | teacher sees live aggregate + incomplete roster; student forced into current voting step |
| Submitted waiting | student submit succeeds before round end | keep student on same step; show submitted-waiting card |
| Overwrite allowed | round still open after prior submit | allow answer change; keep status copy that last valid response will count |
| Duplicate payload deduped | same student resubmits same payload | no extra visual attempt entry; keep stable waiting/submitted state |
| Reconnecting | transport interrupted | show reconnect banner in current shell; preserve current context |
| Reconnected restored | durable snapshot recovered | restore current voting state and latest submit status |
| Late submit rejected | teacher ended round before submit | disable inputs and show explicit round-ended rejection copy |
| Round frozen | teacher ends round | freeze aggregate view, mark round ended, keep named detail optional |
| Runtime degraded after launch | plugin/transport posture worsens post-launch | show in-class warm warning card; classroom continues |

## Interaction Rules

1. Voting remains a classroom-controlled interaction, not an individual quiz flow.
2. Teacher starts and ends the round from the existing control panel.
3. Student submit success never moves the class forward automatically.
4. Aggregate truth is teacher-first: overview before detail.
5. Incomplete roster is a first-class panel, not derived from hidden detail.
6. Named detail is opt-in and folded by default.
7. Launch warnings are visible but nonblocking unless classified as blockers.
8. Post-launch degraded posture becomes classroom-internal honesty, never an automatic shutdown.
9. All runtime result surfaces must use tonal separation, spacing, and chips — never divider-heavy data tables.
