|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 400 | 1.5 |
| Heading | 20px | 600 | 1.2 |
| Display | 40px | 600 | 1.2 |

Rules:

- 日程卡第一信息层固定为 `时间 / 班级 / 地点 / 状态`，其中班级或课程名用
  Heading，时间与状态标签用 Label。
- 导入审核的行级问题说明、冲突解释、AI 建议理由统一用 Body，不再额外引入
  第五种字号。
- 表格式密集数据不升级为小于 14px 的 micro text。

| Dominant (60%) | #f5f7f9 | 页面背景、教师课表主舞台外层、calendar shell、review workspace floor |
| Secondary (30%) | #eef1f3 | hero、sidebar、filters、tonal section、row review 容器、calendar panels |
| Accent (10%) | #0050d4 → #7b9cff | 仅用于主 CTA、当前日期/当前进行中 agenda 标记、审核通过入口、需要明确推进的 primary links |
| Destructive | #b31b25 | 停课、删除待审核批次、撤销 override、拒绝危险变更 |

Accent reserved for: `导入课表`、`审核通过并写入课表`、`查看今日完整日程`、
当前日期 chip、当前进行中 agenda dot/badge、明确已选中的单日 override 入口。

Additional color rules:

- 调课变更但非危险状态使用 tonal secondary surface，不使用 destructive 红。
- `代课` 可使用 tertiary green family 作为语义辅助，但不能升级成新的主品牌色。
- AI 建议卡只可用 secondary tonal + accent 标题，不可用成功绿伪装成“已自动执行”。

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | 导入课表 |
| Empty state heading | 今天还没有生成可执行课表 |
| Empty state body | 先导入并审核课表数据，或检查今天是否被设置为节假日/非教学日。 |
| Error state | 课表生成失败：请先处理导入冲突、缺失映射或无效调课记录，然后重新生成今日议程。 |
| Destructive confirmation | 停课：`确认将本次课程标记为停课？系统会保留原始排课与审计记录。`；删除待审核批次：`确认删除这批导入记录？删除后不会影响已入库课表，但待审核结果将不可恢复。`；撤销单次调课：`确认撤销本次调课？系统会恢复到原始排课结果。` |

Copy rules:

- 所有用户可见文案默认使用简体中文。
- 审核失败与冲突说明必须写出“问题 + 下一步”，不能只写错误码。
- AI 建议的动作按钮统一使用 `查看建议`、`采纳为草案`、`去人工确认`，不出现
  `自动修复`、`一键执行` 之类文案。

## Surface inventory and hierarchy

### 1. Teacher daily agenda surface

- 首屏 route 以教师个人日程为主，不先做学校级运营总览。
- 页面结构固定为：
  1. 单一 agenda hero
  2. 今日议程卡片流
  3. 变更/提醒/AI 建议二级支持区
- hero 展示今日日期、学期/周次摘要、今日课节总数、变更数、下一节课倒计时。
- 主列表使用纵向卡片时间线，不使用后台式大表格。
- 每张 agenda card 第一屏必须可见：`时间`、`班级`、`地点`、`状态`。
- 与教案/课程入口的联动放到卡片下半区或次级操作，不抢第一信息层。

### 2. Import review surface

- 导入入口是“审核台”，不是一键导入向导。
- 页面固定分为两层：
  - 批次摘要层：来源、导入时间、学校范围、总行数、通过/冲突/待确认统计
  - 行级审核层：逐条显示校验、映射、冲突、审批状态
- 行级审核使用卡片或 expandable review rows；不得只给整文件结论。
- 未解决 blocker 时，`审核通过并写入课表` 必须禁用，并在按钮附近显示阻断摘要。

### 3. Override and reschedule surface

- 首发 override 仅支持单次覆盖，不做整周批量改写。
- 新建 override 时，原始排课摘要固定显示在表单顶部，包含原教师、原时间、原教室。
- 可选动作仅三类：`代课`、`停课`、`换时间/教室`。
- 所有 override 表单都必须展示生效日期与审计说明。

### 4. Holiday and non-teaching day surface

- 节假日/非教学日使用 term-aware calendar + tonal list 组合。
- 日历格子优先显示是否教学、是否调休、是否影响 agenda 生成。
- 节假日不是纯视觉注释；保存后必须作为 runtime agenda 生成条件的一部分。

### 5. Reminder surface

- 首发提醒只覆盖：`开课前提醒`、`调课变更提醒`。
- 提醒配置以卡片组呈现：触发时间、对象、渠道、最近执行状态。
- 提醒状态不能假装已发送；必须区分 `已计划`、`发送成功`、`发送失败`、`需重试`。

### 6. AI assistant surface

- AI 助手是建议器，不是执行器。
- 提案卡必须包含：建议标题、理由、影响范围、需要人工确认的字段、来源上下文。
- `采纳为草案` 只生成待确认 proposal，不直接改 schedule runtime。

## Interaction contract

### Agenda status model

- Agenda 状态固定使用：`正常`、`进行中`、`即将开始`、`已变更`、`代课`、`停课`。
- `进行中` 使用 accent badge。
- `已变更` 与 `代课` 使用 secondary/tertiary tonal badge。
- `停课` 使用 destructive 容器色，但只在该条 agenda 内局部高亮。

### Review status model

- Import review 状态固定使用：`待审核`、`校验失败`、`映射待确认`、`冲突待处理`、
  `可入库`、`已批准`、`已拒绝`。
- 同一行同时出现多个问题时，以阻断优先，不叠多枚抢眼 badge。

### Approval and confirmation

- 任何会影响 runtime 课表的动作都必须二次确认。
- 确认弹层正文必须包含：影响对象、影响日期、是否通知、是否保留原始记录。
- AI 建议与插件提案共用同一确认模式：先看 proposal，再人工批准。

### Feedback and read-your-writes

- 写操作成功后，在当前 surface 内显示可见 success region，不只依赖 toast。
- 导入批准、调课保存、节假日更新、提醒配置保存后，都要回填最新摘要卡片。
- 失败反馈优先贴近触发区域，顶部再给简短汇总。

---

## Visual guardrails

- 不使用 1px divider line 分割课表、审核区、日历区。
- 不把 teacher daily agenda 做成 admin spreadsheet 首页。
- 不让导入审核、今日课表、AI 建议同时变成三个强 hero。
- 不用红色承担普通变更语义；红色只给危险或停课动作。
- 不把原始 import rows 暴露成最终教师消费 DTO 视图。
