## ROADMAP

**Milestone:** v3.2 AI LessonAgent 起草闭环
**Archived:** 2026-06-02
**Status:** ✅ SHIPPED
**Closure scope:** Phase 61-66
**Total plans:** 29

## Overview

`v3.2` 把 `v3.0` 已建立的 AI-native platform contracts 真正兑现成一条教师可用的 LessonAgent 起草闭环：provider 抽象层负责密钥隔离、限流和 typed 错误；typed tool 层与 Command Bus 负责受治理的 AI 调用；draft lesson version 继续复用既有 publish/version 真相源；教师在编辑器内完成审校、接受与丢弃；最后由 eval、guardrails 和 `verify:phase` 收口质量闸门。

这个里程碑在 2026-06-01 的 milestone audit 中暴露出真实的跨 phase 断缝：teacher trigger 缺失、run→persist 未桥接、accept/discard 绕过 Command Bus。收尾 Phase 66 没有接受这些缺口为 tech debt，而是逐项补齐生产路径，再完成归档。

## Phases

### Phase 61: AI Provider Abstraction Layer

**Goal**: 建立 `server/ai/providers` 统一抽象层，让调用方通过单一接口完成一次文本/结构化生成，密钥只在服务端 Node runtime 读取，调用受限流/配额保护，失败返回区分可重试的 typed 错误。
**Depends on**: Nothing (first phase of v3.2; reuses v3.0 platform core)
**Plans**: 5 plans

**Details:**

- 建立了 `getProviderConfig`、`getLanguageModel`、`aiGenerateText` / `aiGenerateObject` 的唯一调用面。
- AI provider 密钥被严格限制在 server-only Node runtime；client、Edge 和 plugin 均无泄漏路径。
- 双层固定窗口限流、fail-closed Redis 语义与 typed provider error 完成了基础防护。

### Phase 62: LessonAgent Typed Tool Layer

**Goal**: 建立 `server/ai/tools` LessonAgent 工具层：输入输出在边界处被校验，只能经 DAL / Command Bus 读写，不可直连 DB、不可触 provider key、不可执行任意代码；教师能针对目标课时触发起草，Agent 产出符合 `content`/`task`/`quiz` schema 的步骤包，关键节点写入 v3.0 event bus。
**Depends on**: Phase 61
**Plans**: 4 plans

**Details:**

- 交付 `createDraftLessonStepTool`、prompt 编排、no-leak 边界测试和 `lesson.draft.run` 命令 handler。
- LessonAgent 对外只暴露 server-only `draftLessonStep(...)` facade，底层统一经 Command Bus 编排。
- 起草的 requested / tool.invoked / produced / failed 关键节点有了 typed 事件语义。

### Phase 63: AI Draft Chain into Draft Lesson Version

**Goal**: 打通起草写入链路：Agent 产出经 Command Bus 写入 draft lesson version，复用既有 publish/version 模型而非新建第二真相源；写入幂等且 replay-safe；draft 在数据上标注 AI 来源、与教师手工编辑可区分，且不会自动发布给学生。
**Depends on**: Phase 62
**Plans**: 4 plans

**Details:**

- 增加了 `draftLessonVersions` 镜像表、AI provenance 字段与 `(lessonId, sourceCommandId)` 幂等约束。
- `lesson.draft.persist` 命令、handler、registry 与 summary-only persisted 事件全部落地。
- DAL 写路径确保起草只落 draft，不污染 live lesson，也不创造第二真相源。

### Phase 64: Teacher Review & Accept-Publish Surface

**Goal**: 交付教师审校面：教师能看到 AI 起草与当前课时的步骤级 diff（新增/修改/删除），能逐项或整体编辑后再决定去留，能接受起草进入既有发布链路或丢弃且不影响原课时，界面对齐 Stitch 项目 `5322129002350954765` 与 `DESIGN.md`。
**Depends on**: Phase 63
**Plans**: 4 plans

**Details:**

- `LessonDraftReviewDTO`、diff 分类、draft lifecycle 字段与 apply/discard DAL 形成完整审校数据模型。
- apply/discard Server Actions 与 `lesson.draft.accept` / `lesson.draft.discard` 命令契约对齐。
- 编辑器内嵌 `mode=review`、glass discovery prompt、单列 diff workspace、右侧 edit panel 与全局确认条，完成 Stitch/DESIGN 对齐。

### Phase 65: Eval, Guardrails & verify:phase Close Gate

**Goal**: 建立 AI 起草链路的质量与闭环闸门：一组可重复运行的 eval 验证起草输出在 schema 合法性与基本教学结构上达标；guardrails 拦截越界输出（非法 step 类型、超长、注入禁止内容）并记录；提供 `verify:phase` close gate 对整条链路做端到端回归，作为里程碑 close 的单一权威闸门。
**Depends on**: Phase 64
**Plans**: 5 plans

**Details:**

- shared corpus 为有效草稿和 counter-example 提供统一 fixture truth。
- `DraftGuardrailRejection`、`assertStepWithinGuardrails` 与 `lesson.draft.rejected` 形成越界输出的 typed 拒绝链。
- `verify:phase` 把 build、回归 Vitest 与 D-10 静态边界检查收口为单一 authoritative close gate。

### Phase 66: Wire AI LessonAgent draft loop end-to-end: bridge run→persist, add teacher draft trigger, route accept/discard through Command Bus, fix version:0 event payload

**Goal**: 教师能在课时编辑器触发 LessonAgent 起草，AI 产出的步骤包经 Command Bus 写入 draft lesson version 并可在审校界面接受（进入既有发布链路）或丢弃，accept/discard 全程走命令总线且领域事件携带真实 draft 版本号。
**Depends on**: Phase 65
**Plans**: 7 plans

**Details:**

- 修复了 `version: 0` 数据链，并让 accept/discard 事件携带真实 draft version。
- 在 `draftLessonStep` 后桥接 `lesson.draft.persist`，使 run→persist 成为真实生产路径而非孤立测试链。
- 新增教师侧 `draftLessonWithAgentAction` 与编辑器「AI 起草」触发器，同时将 accept/discard 改由 Command Bus producer 驱动。
- 最终用组装态 e2e 规格和 Playwright 视觉验证关闭 teacher trigger、review、publish 链路的生产接缝。

## Milestone Summary

**Key Decisions:**

- 坚持 `provider -> typed tool -> Command Bus -> draft lesson version -> review/apply` 的单链路收口，而不是为 AI 起草另建第二套真相源。
- provider key 继续严格限制在 server-only Node runtime；Redis 计数不可用时保持 fail-closed，而不是为了本地可跑通降低保护强度。
- 面对 milestone audit 暴露的跨 phase 断缝，优先修真实生产链路，再回写 traceability / archive，而不是用单 phase 完成度替代里程碑闭环。

**Issues Resolved:**

- provider、tool、command、draft persistence、review surface 和 close gate 终于被接成了一条真实 LessonAgent 起草闭环。
- 关闭了 teacher trigger 缺失、run→persist 未桥接、accept/discard 绕过 Command Bus、event `version: 0` 等 v3.2 close blocker。
- `REQUIREMENTS.md` 的陈旧追溯状态被统一回写为最终 shipped truth（18/18 complete）。

**Issues Deferred:**

- 多 Agent 协作、RAG/Qdrant、MCP 外部工具、plugin 触达 AI、provider 多模型路由继续保持在本里程碑外。
- 本地/沙箱环境下的“真实 LLM + Redis”端到端生成验证仍需外部基础设施；本次 close 以 mock-provider automated proof + Playwright 视觉验证完成验收。

**Technical Debt Incurred:**

- LessonAgent 的 live draft path 在本地开发和 sandbox 中依然依赖额外 provider/Redis 配置；未来若要把“真实生成验收”纳入日常 close posture，需要补一条可重复的本地 bootstrap 或 staging proof lane。
