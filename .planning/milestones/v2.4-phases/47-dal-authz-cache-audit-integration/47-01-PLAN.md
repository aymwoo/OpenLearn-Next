# Phase 47-01 PLAN: DAL, Auth, Cache & Audit Integration

## 1. 计划目标 (Objectives)
* **安全鉴权整合**：强化 `src/lib/dal/plugin-data.ts`，加入针对插件自声明权限 (Manifest) 检查以及操作者（Actor）真实角色与范围的深度双层鉴权拦截。
* **高响应级联缓存刷新**：在插件扩展数据与自有业务数据的 mutation 操作中，强制嵌入 Next.js `revalidateTag` / `updateTag` 对相应插件缓存和核心实体（Lesson, Step, Resource）缓存的链式级联失效。
* **物理审计日志记录**：自动将所有插件 lifecycle 转移以及 DAL 层关键写操作分别精确记录于物理表 `governanceAudit` 与 `pluginActionAudit` 中。
* **自动化 Close Gate 校验**：编写并落地一键验证脚本 `scripts/verify-phase47-dal-integration.ts` 并注册在 `"verify:phase47"` 中，完成向前级联兼容性回归。

## 2. 核心功能与架构实现方案 (Implementation Steps)

### A. 双层鉴权与自声明权限校验 (`src/lib/dal/plugin-data.ts`)
我们将在 `plugin-data.ts` 的 `upsertPluginExtension` 等 mutation 接口中追加以下前置拦截机制：
1. **真实用户（Actor）权限拦截**：
   - 提取并校验 Actor 属于本校活动教师；
2. **插件自声明权限验证**：
   - 从 `pluginRegistrations` 中根据 `pluginId` 捞出 `manifestJson`。
   - 解析 `manifestJson.permissions` 数组。
   - 针对 `entityType === "lesson" | "step"` 的扩展修改，强制断言 manifest 中声明了对应的 `"lesson:write"` 或 `"lesson:extension:write"`。如果缺失，立刻抛出 `Error("PLUGIN_MANIFEST_PERMISSION_DENIED")` 并拦截写操作。

### B. Next.js 级联缓存重置机制
在 `upsertPluginExtension` 执行完 SQLite 数据更新后，触发级联 revalidation：
- 显式调用 `revalidateTag(`plugin:ext:${schoolId}:${pluginId}:${entityId}`)`；
- 根据扩展实体类型进行父级回溯，查询核心实体归属：
  - 如果是 `lesson`：获取对应的 `courseId`，接着链式失效 `revalidateTag("lesson:" + entityId)` 和 `revalidateTag("course:" + courseId)`。
  - 如果是 `step`：获取所属的 `lessonId` 并查询对应 `courseId`，接着链式失效 `revalidateTag("step:" + entityId)`，`revalidateTag("lesson:" + lessonId)` 和 `revalidateTag("course:" + courseId)`。

### C. 物理审计日志自动落盘
在 DAL 写入成功时，作为同一物理事务（或者关联异步操作，SQLite 环境下推荐采用同一物理事务以保障一致性）追加对审计表的数据记录：
- 往 `pluginActionAudits` 表中插入记录：
  - `actorId`
  - `schoolId`
  - `pluginId`
  - `action`: `"upsert_extension"`
  - `targetType`: `"extension"` 或传入类型
  - `targetId`: `entityId`
  - `payloadJson`: 记录写入参数概要
- 往 `governanceAudits` 记录中插入权限允许决策：
  - `decision`: `"allow"`
  - `reason`: `"manifest_and_actor_permission_verified"`
