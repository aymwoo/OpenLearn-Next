# Phase 48-01 PLAN: Lifecycle & Uninstall Semantics

## 1. 计划目标 (Objectives)

* **生命周期一致流转控制**：实现规范的插件生命周期状态流转矩阵验证，在 `src/lib/dal/plugins.ts` 中升级 `transitionPluginLifecycle`，确保每一次流转都受到 `assertPluginLifecycleTransition` 转换机规则的合法约束。
* **物理事务流水与审计**：保证生命周期的变更是物理原子性的。每次状态流转同步在物理事务中写入 `pluginLifecycleTransitions` 表以持久化状态变更证据，并在 `pluginActionAudits` 和 `governanceAudits` 中自动沉淀审计凭证。
* **卸载依赖安全预检**：开发 `preflightUninstallPlugin` 前端-服务端直连 API，在卸载前严密盘点 `pluginLessonExtensions`、`pluginLessonStepExtensions`、`pluginResourceExtensions` 和 `pluginOwnedBusinessData` 中属于本校与本插件的物理数据，报告引用概况，且严格阻断内置系统级默认插件的卸载动作。
* **物理事务彻底卸载清理**：实现 `uninstallPlugin` 服务层 API，在一键确认后通过主表注册记录删除，触发 onDelete "cascade" SQLite 级联外键清除插件在所有扩展/业务物理表中的数据资产。
* **自动化 Close Gate 校验**：编写 `scripts/verify-phase48-lifecycle-and-uninstall.ts`，锁定静态安全规范、单元测试执行及 44-47 阶段全量回归。

## 2. 核心功能与架构实现方案 (Implementation Steps)

### A. 生命周期转换状态机与事务流水
1. **状态转换矩阵校验**：
   - 编写 `assertPluginLifecycleTransition(fromState, toState)` 函数，比对状态矩阵，若发生非法跳步，直接抛出 `Error("LIFECYCLE_ILLEGAL_TRANSITION")`。
2. **事务状态变更接口**：
   - 暴露 `transitionPluginLifecycleAction(actorId, schoolId, pluginId, targetState, reason)`。
   - 提取并校验操作者是该学校的活动教师身份。
   - 查询 `pluginRegistrations` 当前的 `lifecycleState`、`sourceType` 等。
   - 校验当前生命周期向 `targetState` 的转换。
   - 开启物理事务 `db.transaction`：
     - 更新 `pluginRegistrations` 状态，如果 `targetState === "enabled"`，设置 `enabled = true`，否则设置 `enabled = false`。
     - 往 `pluginLifecycleTransitions` 插入演进记录（记录 `fromState`, `toState`, `reason`, `actorId`）。
     - 往 `pluginActionAudits` 写入操作记录，往 `governanceAudits` 写入流转批准决策。

### B. 卸载依赖预检 (Preflight) 与卸载 API
1. **预检依赖盘点 (`preflightUninstallPlugin`)**：
   - 如果目标插件是内置默认插件（`sourceType === "default"`），直接返回 `blocked: true, reason: "UNINSTALL_BLOCKED_DEFAULT_PLUGIN"`（或抛出对应异常）。
   - 查询各扩展物理表在该 `schoolId` 且该 `pluginId` 下的数据总记录数：
     - `pluginLessonExtensions` -> `lessonExtCount`
     - `pluginLessonStepExtensions` -> `stepExtCount`
     - `pluginResourceExtensions` -> `resourceExtCount`
     - `pluginOwnedBusinessData` -> `ownedBusinessCount`
   - 合计所有计数，返回包含计数详情和被影响的核心课时/资源/独立业务清单的结构数据给操作人。
2. **安全级联卸载 (`uninstallPlugin`)**：
   - 检验前置条件，如果是默认插件，抛出 `UNINSTALL_BLOCKED_DEFAULT_PLUGIN`。
   - 开启物理事务 `db.transaction`：
     - 写入 `uninstall` 治理审计至 `governanceAudits`；
     - 删除该插件在 `pluginRegistrations` 中的记录；
     - 由于外键 `references pluginRegistrations.id, { onDelete: "cascade" }` 的物理保护，其余扩展数据将在事务中干净地自动删除。

## 3. 命名规范与静态校验 (Static Security Audit)

在 `scripts/verify-phase48-lifecycle-and-uninstall.ts` 脚本中追加对生命周期管理的代码静态安全审计：
- **默认插件卸载防御**：静态检测 `uninstallPlugin` 或其关联 API，断言其中含有 `sourceType === "default"` 的严格拦截条件。
- **事务与级联记录机制**：扫描 DAL 层修改，断言 `db.transaction` 在生命周期流转和卸载中被明确执行，并且对 `pluginLifecycleTransitions` 表有且仅有规范的 insert 写操作。

## 4. 自动化测试与验证 (Validation Strategy)

* **单元测试文件**：在 `src/lib/dal/plugins.test.ts` 中升级测试，完全覆盖以下场景：
  - **非法生命周期转移拦截**：测试从 `installed` 直接强切到 `suspended` 或 `failed` 被正确抛出 `LIFECYCLE_ILLEGAL_TRANSITION` 错误。
  - **合法生命周期事务对齐**：测试启用或停用非默认插件后，`pluginRegistrations` 状态被成功更新，且 `pluginLifecycleTransitions` 完美增加变更行，物理审计日志正确记录。
  - **默认插件卸载强拦截**：测试尝试卸载内置系统插件，验证接口正确抛出 `UNINSTALL_BLOCKED_DEFAULT_PLUGIN` 报错。
  - **级联删除物理验证**：测试删除外部插件注册记录后，断言对应测试表中的扩展物理记录被完全物理清除，无残留行。
