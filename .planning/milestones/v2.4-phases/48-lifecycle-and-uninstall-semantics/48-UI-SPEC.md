## Phase 48 visual and interaction contract

Phase 48 的 operator-facing lifecycle / uninstall surface 固定挂在
`Settings Labs` 体系内，延续 `settings-surface.tsx`、Phase 42 async operator
和 `plugin-marketplace-surface.tsx` 的产品语言：Lexend、tonal surfaces、
no-line、ambient shadow、glass/gradient CTA。它不是 generic admin console，
也不是 marketplace 的 destructive fork。

### 1. Surface scope and IA

1. 生命周期管理主面固定放在 `Settings Labs` 内的插件管理区，允许继续留在
   `/settings/labs` 右侧插件区，或拆成 `/settings/labs/plugins` 子页；但入口名
   必须仍属于 Labs 语境，而不是“系统后台 / 插件控制台”。
2. `plugin-marketplace-surface.tsx` 继续是 **discoverability surface**：只看系统内置
   插件、默认状态、启用/停用，不承载 kill switch、preflight uninstall、danger
   zone 或删除确认。
3. Settings Labs 中的插件卡片必须明确回答两类问题：
   - 这个插件现在处于什么 lifecycle posture
   - 我此刻能执行什么动作、哪些动作被禁止、为什么
4. 页面信息层级固定为：
   - 顶部 hero：解释“Lifecycle & Uninstall Semantics”不是普通开关
   - 插件列表：每个插件的当前 posture + 可执行动作
   - 选中插件详情或展开区：preflight / ownership / kill switch / uninstall
     contract
   - 底部 danger zone：仅对可删除插件显示

### 2. Five semantics must be visually distinct

UI 必须把以下五种语义做成不同层级，不允许用一个 toggle 混过去：

| Semantic | 中文标签 | UI pattern | Visual tone | What it means |
|----------|----------|------------|-------------|---------------|
| Install | 安装 | primary CTA / status entry | accent gradient | 把插件纳入当前学校治理范围，产生正式 registration |
| Enable | 启用 | primary or secondary positive action | accent | 恢复运行能力；保留已有数据 |
| Disable | 停用 | secondary action | neutral | 关闭运行能力；保留数据和历史记录 |
| Suspend / kill switch | 紧急挂起 / 总开关关闭 | warning-toned action + explicit operator note | amber/warning surface, not red delete tone | 因风险或故障立即阻断运行，不等于删除，不清数据 |
| Uninstall | 卸载 | destructive flow in danger zone only | destructive | 删除注册并触发级联清理；必须先过 preflight |

规则：

1. `Enable` 和 `Install` 不能共用同一标签。未注册时只能看到“安装插件”；已注册但停用时显示“启用插件”。
2. `Disable` 不能写成“删除”或“移除”；必须配文说明“仅停止运行，保留数据”。
3. `Suspend / kill switch` 必须和普通 `Disable` 区分。它的说明文案必须包含“紧急”“总开关”或“立即阻断运行能力”。
4. `Uninstall` 只能出现在详情区或展开卡片的 danger zone，不能放进与 enable/disable 同一行的常规次按钮组。

### 3. Plugin card layout contract

每张插件卡片至少包含四层信息，且用 tonal nesting 分层，不用 divider lines：

1. **Identity row**：插件名 + source posture + built-in/default posture。
2. **Registry meta row**：`pluginKey`、`dbNamespace`、`sourceType`、`installSource`。
3. **Runtime posture row**：
   - lifecycle state
   - enabled/disabled 文案
   - kill switch posture
   - data posture 文案（保留 / 可清理 / 默认插件不可删除）
4. **Action row**：仅展示当前允许的 1-3 个动作，不堆满所有按钮。

卡片视觉规则：

1. 外层用 `bg-surface-container-low` 或现有 section shell，内层操作卡用
   `bg-surface-container-lowest`。
2. 当前选中或最近操作的插件卡允许用 accent ghost glow 强调；不要用边框。
3. blocked 状态使用 `error-container` / warm warning tonal block，不使用纯红实底大面积铺满。
4. built-in / default posture 必须优先于 registry id 展示。

### 4. Lifecycle state mapping

前端展示必须统一映射后端 lifecycle state，不允许同一 state 多套中文。

| Lifecycle state | 中文标签 | Secondary copy | Badge tone |
|-----------------|----------|----------------|------------|
| installed | 已安装，待启用 | 已进入学校治理范围，但尚未恢复运行 | neutral |
| enabled | 已启用 | 运行能力可用，保留统一审计 | accent |
| disabled | 已停用 | 已停止运行，数据与历史记录仍保留 | neutral |
| suspended | 已挂起 | 已被总开关或风险控制阻断，请人工确认后恢复 | warning |
| failed | 异常失败 | 当前运行未成功，先查看原因与恢复路径 | destructive/warning mix |
| mounted | 已挂载 | 运行准备阶段，仍属于活跃态 | accent-muted |
| ready | 已就绪 | 运行能力已准备，可继续执行 hook | accent-muted |

规则：

1. `mounted` 与 `ready` 不得被视觉上归类为“停用”。
2. 所有状态都必须同时用中文文案 + tonal badge 表达，不能只看颜色。
3. `failed` 必须伴随一句可读说明，指出下一步应恢复、停用还是继续排查。

### 5. Action availability rules

动作可见性必须由当前 posture 决定，planner 不得把所有按钮永久显示。

| Current posture | Show | Hide / disable |
|-----------------|------|----------------|
| not installed | 安装插件 | 启用、停用、挂起、卸载 |
| installed / disabled | 启用插件、查看 preflight（若允许删除） | 停用、挂起 |
| enabled / mounted / ready | 停用插件、紧急挂起 | 安装 |
| suspended | 恢复启用、保持停用 | 再次挂起 |
| failed | 查看原因、恢复启用或停用 | 直接显示成功态文案 |
| built-in default plugin | 启用 / 停用 | 卸载、删除、清理数据 |

补充规则：

1. `kill switch` 如果已开启，主卡片首要动作是“解除挂起并重新启用”或“保持停用”，而不是重复展示“开启总开关”。
2. 默认插件的卡片永远不显示 uninstall CTA，即使后端返回更多信息。
3. 对可删除外部插件，常规卡片只显示“查看卸载影响”入口，不直接显示最终删除按钮。

### 6. Preflight uninstall contract

卸载前必须先展示 preflight 结果。该结果是一个独立内容块，不是 toast。

preflight block 固定包含：

1. 结果标题：`卸载前检查`。
2. posture summary：
   - 可继续卸载
   - 存在依赖，需谨慎确认
   - 已阻断，当前不可卸载
3. dependency summary tiles，至少四项：
   - lessons
   - lesson steps
   - resources
   - plugin-owned data / 历史记录
4. blocked reason：默认插件、non-deletable posture 或其他治理阻断。
5. next-step sentence：告诉 operator 现在该停在这里、返回启停，还是继续确认卸载。

展示规则：

1. 如果 preflight `blocked = true`，danger zone 只显示阻断说明，不显示最终确认按钮。
2. 如果有依赖计数但允许继续，必须用中文诚实表述“继续卸载将删除这些关联数据”。
3. impacted IDs 默认不在首屏平铺；先展示计数摘要，再通过折叠区查看样本项或明细列表。
4. preflight 结果必须和具体插件绑定，不能做成全局弹窗共享状态。

### 7. Kill switch and suspend contract

kill switch 是 operator-facing risk control，不是普通停用替身。

1. 在插件详情区提供独立 `Runtime Safety` 或 `运行保护` 块。
2. kill switch 控件使用 warning tonal container，不使用 destructive red。
3. 文案固定语义：
   - 开启时：`立即阻断该插件的运行能力，保留数据与历史记录。`
   - 关闭时：`解除紧急挂起后，仍需按当前 lifecycle posture 决定是否重新启用。`
4. 如果 kill switch 已开启，状态区必须显示 `已挂起 / 总开关开启` 双信息，而不是只显示一个布尔值。
5. kill switch 操作需要轻确认，可用 popover confirm；不需要重型二次弹窗。
6. kill switch 成功后，UI 应立即把 posture 切到 `suspended` 语义，而不是继续显示 enabled badge。

### 8. Danger zone and uninstall confirmation flow

danger zone 只对 **非默认、可删除** 插件展示，且固定放在详情面底部。

结构顺序固定：

1. danger zone 标题 + 一句不可逆说明。
2. preflight 结果摘要。
3. destruction scope copy：明确删除的是“注册记录 + 插件拥有数据”，不是课程核心真相本身。
4. confirmation control。

确认交互规则：

1. 使用 `Dialog`，不用 inline final button 直接删。
2. Dialog 第一屏必须重复展示：插件名、sourceType、是否默认插件、preflight 计数摘要。
3. 确认文案必须明确区分：
   - 停用 ≠ 卸载
   - 挂起 ≠ 卸载
   - 卸载会级联清理插件数据
4. 最终 destructive CTA 固定使用动词 + 对象：`确认卸载插件`。
5. 取消按钮必须是次级样式，留在左侧或视觉弱位；确认按钮用 destructive tone，不使用 accent gradient。
6. 若后端在最终卸载时仍返回阻断错误，Dialog 内应显示诚实错误：`预检结果已过期或治理规则已变化，请重新检查后再试。`

### 9. Default plugin non-deletable posture

默认插件和 built-in 插件必须贯穿整个 UI 保持“可启停、不可删除”的产品语义。

1. 卡片上固定出现 `系统内置` 或 `默认插件` badge。
2. 详情中固定出现说明块：`该插件由系统提供，可启用或停用，但不会作为可删除扩展处理。`
3. preflight 对默认插件不显示“可继续卸载”；直接显示 blocked posture。
4. marketplace 延续现有语义：
   - 只显示启用 / 停用
   - 不出现 danger zone
   - 不出现 delete / uninstall 文案
5. Settings Labs 若列出默认插件，也只能展示 enable/disable 与 kill switch；uninstall 区域以只读 blocked notice 替代。

### 10. Marketplace contract remains non-destructive

`plugin-marketplace-surface.tsx` 本 phase 只需保持 discoverability 与默认插件语义一致，不转成 destructive management surface。

必须维持：

1. Hero 持续强调“仅启用 / 停用，无删除语义”。
2. 卡片文案继续说明“不会以删除动作呈现”。
3. 可以补一个 link 回到 Labs 的“运行管理 / 生命周期管理”，但不能在 marketplace 卡片中新增 uninstall 按钮。
4. marketplace 中的状态名称要与 Labs 一致；至少 `已启用 / 已停用`、`系统内置`、`默认开启` 文案保持一致。

### 11. Empty, loading, and error states

1. **Loading**：插件列表 skeleton 使用白色 inset cards，保留 badge 和 action bar 骨架；不要整页 spinner。
2. **Empty**：说明“尚未注册插件生命周期项”，并给出下一步“完成注册或回到 marketplace 查看默认插件”。
3. **Error**：若 lifecycle action 失败，错误信息出现在对应插件卡片或 dialog 内，不能只靠全局 toast。
4. **Preflight stale**：若 preflight 结果失效，danger zone 内显示 warning block，并要求重新检查。

### 12. Feedback and motion

1. 成功反馈用轻量 inline success note 或 toast，语气必须诚实：
   - `插件已停用，历史记录仍保留。`
   - `已开启紧急挂起，运行能力已阻断。`
   - `卸载已提交，正在移除注册与插件数据。`
2. 状态切换动效控制在 150ms-200ms，以 tonal transition、badge fade、card glow 为主。
3. danger zone dialog 只允许轻微 opacity / scale entrance，不使用强烈晃动或警报动画。

### 13. Accessibility and focus behavior

1. 所有 lifecycle 状态必须文本可读，不依赖颜色判断。
2. kill switch、disable、uninstall 三类动作必须各自有不同 aria/可读标签。
3. Dialog 打开后焦点先到标题或首句风险说明，不直接跳到 destructive CTA。
4. 最终 destructive CTA 不能默认 focus。
5. 焦点样式沿用 `src/app/globals.css` 的 primary outline；高风险区可用 ghost-border + tonal fill，不可加 1px 实线框。

### 14. Explicit do-not-build list

1. 不要把 Settings Labs 做成 generic plugin admin table。
2. 不要用红色按钮同时承载 disable、suspend、uninstall。
3. 不要让 uninstall 绕过 preflight 直接执行。
4. 不要在 marketplace 中加入 destructive management。
5. 不要把默认插件展示成“可删除但会报错”；UI 必须前置表达不可删除。
6. 不要使用 1px divider lines 分隔状态区、动作区、danger zone。

### 15. Source-backed defaults used in this contract

- **From `ROADMAP.md` + `REQUIREMENTS.md` + `SPEC.md`**: LIFE-01 至 LIFE-04，五种生命周期语义、停用保留数据、preflight 检查、默认插件不可删除。
- **From `48-VERIFICATION.md`**: 当前真实 gap 是 Settings Labs 只接 enable/disable，缺 kill switch、preflight uninstall、danger zone confirm flow；marketplace 必须维持 non-destructive posture。
- **From `48-REVIEW.md`**: 前后端 state 与 uninstall block 语义需一致，`mounted` / `ready` 不能被视觉上误判为 inactive，preflight 与最终卸载阻断条件必须同一套表达。
- **From `settings-surface.tsx`**: 现有 Settings Labs tonal shell、quick-link、插件卡片元数据与 built-in copy 可继承，但要扩展为 lifecycle contract。
- **From `plugin-marketplace-surface.tsx`**: marketplace 的“系统内置 / 默认开启 / 仅启用停用”语气继续保留。
- **From `DESIGN.md`, `globals.css`, `teacher-surface-rhythm.ts`, `button.tsx`**: Lexend、surface tokens、ambient shadow、no-line、gradient CTA、44px+ action targets。
- **From `42-UI-SPEC.md`**: Settings Labs operator surface 仍然采用产品面表达，不退化成 ops dashboard 或 dense table。
