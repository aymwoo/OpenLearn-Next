# Phase 45-01 PLAN: Extension & Plugin-Owned Schema Patterns

## 1. 计划目标 (Objectives)
* 在 SQLite 物理层中，为三个核心实体提供专属扩展物理表，并为通用多态业务对象提供独立自有物理表。
* 物理层面强制绑定外键级联删除（on delete cascade）和联合唯一性索引，防止并发冲突和孤儿数据。
* 编写内置安全多租户校验的统一 DAL 服务 Seam，严密防御越权行为和租户跨校越界注入。
* 编写完整的单元测试与物理级联删除回归测试，通过 `vitest` 进行 100% 绿牌回归。

---

## 2. 物理 Schema 变更与定义 (Physical Schema Changes)

我们将在 `src/db/schema.ts` 中增加如下物理表：

### A. 物理扩展表规范
1. **`plugin_ext_lesson`**
   - 关联 `schools.id`、`pluginRegistrations.id`、`lessons.id`。
   - 联合唯一索引: `(schoolId, pluginId, lessonId)`。
2. **`plugin_ext_lesson_step`**
   - 关联 `schools.id`、`pluginRegistrations.id`、`lessonSteps.id`。
   - 联合唯一索引: `(schoolId, pluginId, lessonStepId)`。
3. **`plugin_ext_resource`**
   - 关联 `schools.id`、`pluginRegistrations.id`、`resources.id`。
   - 联合唯一索引: `(schoolId, pluginId, resourceId)`。

### B. 插件自有业务表规范
1. **`plugin_owned_business_data`**
   - 关联 `schools.id`、`pluginRegistrations.id`。
   - 包含多态标识 `key` 以及 `payloadJson`。
   - 索引: `(schoolId, pluginId, key)`。

## 3. DAL 接口与安全防御 (DAL Seam & Security Aspect)

在 `src/lib/dal/plugin-data.ts` 中实现：
* `upsertPluginExtension(actorId, schoolId, pluginId, entityType, entityId, payloadJson)`
* `getPluginExtension(actorId, schoolId, pluginId, entityType, entityId)`
* `upsertPluginOwnedBusinessData(actorId, schoolId, pluginId, key, payloadJson)`
* `getPluginOwnedBusinessData(actorId, schoolId, pluginId, key)`

### 安全断言逻辑：
1. `assertTeacherManagerScope(actorId, schoolId)`。
2. 多租户越权检验：查询对应的 `lesson`/`lessonStep`/`resource` 在数据库中物理存储的真实 `schoolId`，断言必须与操作传入的 `schoolId` 绝对一致。
