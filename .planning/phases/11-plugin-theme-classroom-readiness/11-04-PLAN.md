<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser form -> Server Action | Teacher-entered step payload content crosses from client to server. |
| Server Action -> DAL | Validated DTO crosses into database update. |
| Draft lesson state -> Published snapshot | Draft edits must not become student-visible until publish. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-04-01 | T | `autosaveLessonStepAction` payload | mitigate | Keep `lessonStepPayloadSchema` as action/DAL validation boundary; malformed content/task/quiz payloads return validation errors. |
| T-11-04-02 | E | `updateLessonStep` | mitigate | Preserve `assertActiveTeacher()` and scoped lesson access in DAL; UI passes only `stepId`, not trusted school ownership. |
| T-11-04-03 | I | Draft visibility | mitigate | Update only draft `lessonSteps`; student player consumes `publishedLessonVersions.snapshotJson` until teacher publishes. |
| T-11-04-04 | R | Save feedback | mitigate | Show save/conflict status from action result and use existing revision/cache tags to prevent stale authoring reads. |
| T-11-04-05 | D | Invalid quiz/task inputs | mitigate | Client builds minimum valid payloads and action rejects incomplete options/submission types via Zod. |
</threat_model>
