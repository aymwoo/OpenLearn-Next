<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Plugin/theme manifest -> Server Action/DAL | Untrusted JSON theme token values enter validation and persistence. |
| Cookie -> ThemeInjector | User-controlled `activeThemeId` selects a theme record. |
| Theme tokens -> CSS variables | Stored token values are rendered into a root style tag. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-02-01 | T/XSS | `ThemeInjector` | mitigate | Inject only variables produced by `compileThemeTokensToCssVariables()` after `ThemeTokenRegistrySchema` and `validateThemeTokens()`; no plugin-supplied selectors or HTML. |
| T-11-02-02 | I/E | Actor-scoped theme DAL usage | mitigate | Load active themes through current actor/current-school scoped DAL, require `validationStatus === "valid"`, and return null for cross-school or unauthorized theme IDs. |
| T-11-02-03 | S/T | `activeThemeId` cookie | mitigate | Treat cookie as non-sensitive preference only; validate through actor-scoped DB lookup and ignore missing/invalid/unauthorized IDs. |
| T-11-02-04 | T | CSS variable naming | mitigate | Unit-test `--color-surface-container-low` output and absence of `--surface-*` drift. |
| T-11-02-05 | D | Layout rendering | accept | Invalid/missing theme returns null and default globals.css remains active; no runtime exception for bad cookie. |
</threat_model>
