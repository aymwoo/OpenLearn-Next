<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Plugin manifest -> registry | Declarative third-party-like metadata enters stored config. |
| Plugin action request -> dispatcher | Hook execution chooses a system-owned action. |
| Theme token JSON -> CSS variables | Declarative tokens become UI styling values. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-05-01 | E | `dispatchPluginAction` | mitigate | Switch only on `PLUGIN_ACTION_ALLOWLIST`; no manifest handler paths, `eval`, or dynamic imports. |
| T-06-05-02 | T | `PluginManifestSchema`/DAL | mitigate | Parse manifest with Zod and reject unknown executable surfaces through DTO constraints. |
| T-06-05-03 | R | `pluginActionAudits` | mitigate | Record hook runs, denied actions, permission failures, and kill-switch state. |
| T-06-05-04 | I | Theme tokens | mitigate | Compile only known CSS variables; reject arbitrary CSS/script fields. |
| T-06-05-05 | D | Plugin hook runs | mitigate | Kill switch and enabled flags deny execution before dispatch. |
</threat_model>
