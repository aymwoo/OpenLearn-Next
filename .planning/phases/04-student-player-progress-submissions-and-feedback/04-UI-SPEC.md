# Phase 04 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by
> gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

Phase 04 must extend the existing manual Tailwind v4 design system from
`DESIGN.md`, `src/app/globals.css`, and the Phase 01 player/student shells. Do
not initialize or import a generic shadcn preset in this phase: the repository
already has project-specific tonal surfaces, Lexend, no-line separation, and
gradient CTA primitives.

| Property | Value |
|----------|-------|
| Tool | none — manual Tailwind v4 tokens already present |
| Preset | not applicable |
| Component library | local primitives + Radix Slot only where already used |
| Icon library | lucide-react |
| Font | Lexend via `next/font/google` and `--font-sans` |

Existing primitives to reuse: `Button`, `Card`, `Badge`, and `Skeleton`. Any new
input, textarea, tab, step rail, or feedback component must be styled locally
with the same tokens rather than adding a border-heavy UI kit.

---

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge internal gaps, compact status dots |
| sm | 8px | Compact element spacing, stacked metadata rows |
| md | 16px | Default element spacing, form field groups, step controls |
| lg | 24px | Card padding, player content block padding |
| xl | 32px | Layout gaps between dashboard/player regions |
| 2xl | 48px | Hero-to-content section breaks on desktop |
| 3xl | 64px | Page-level breathing room on wide screens |

Exceptions: icon-only and compact navigation controls must keep a minimum
44px hit target; primary learning and feedback actions use the existing
`Button` minimum height of 48px.

---

## Typography

Phase 04 uses exactly four text sizes and two weights. Do not introduce extra
weights for score, progress, or feedback emphasis.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 400 | 1.4 |
| Body | 16px | 400 | 1.5 |
| Heading | 24px | 600 | 1.2 |
| Display | 48px | 600 | 1.1 |

Instructional lesson text, submission prompts, quiz explanations, and teacher
feedback must use Body. Step names, card titles, and panel headings use Heading.
Only the dashboard welcome and lesson title hero may use Display.

---

## Color

Use the existing `DESIGN.md` and `globals.css` tokens. State labels must include
text; never communicate progress, score, error, or feedback status by color
alone.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f5f6f7` / `surface` | Page background, cached player shell, calm reading canvas |
| Secondary (30%) | `#eff1f2` / `surface-container-low` and `#ffffff` / `surface-container-lowest` | Dashboard lesson cards, player step rail, task/quiz panels, teacher review cards |
| Accent (10%) | `#005da7` → `#68abff` gradient and `#68abff` containers | Resume CTA, current step marker, submit attempt CTA, feedback send CTA, active filter pill, focus ring |
| Destructive | `#b31b25` / `error` | Only failed submission/error recovery text; no destructive learning action in Phase 04 |

Accent reserved for: `继续学习`, `提交答案`, `提交任务`, `发送反馈`, current
step indicator, active teacher review filter, progress focus ring, and quiz score
highlight. Success uses `tertiary-container` for completed steps and submitted
states. Do not use accent for every link, every icon, or decorative background.

## Copywriting Contract

All user-facing copy must be Simplified Chinese, direct, and reassuring. The UI
must make the learning state clear before asking the student to act.

| Element | Copy |
|---------|------|
| Primary CTA | `继续学习` on dashboard and resume surfaces; `提交答案` for quiz; `提交任务` for task; `发送反馈` for teacher feedback |
| Empty state heading | `还没有可学习的课时` |
| Empty state body | `老师发布课时后，这里会显示你的学习任务。你可以先查看课程列表。` |
| Error state | `学习状态暂时没有同步成功，请刷新页面或稍后重试。你的已提交记录不会丢失。` |
| Destructive confirmation | `无` — Phase 04 不提供学生删除提交或教师删除反馈操作 |

Required microcopy by state:

- Resume target: `从第一个未完成步骤继续` or `老师正在带你进入当前步骤`.
- Cached shell loading: `正在加载你的学习进度...`.
- Latest submission loading: `正在读取最近一次提交...`.
- Content complete: `已完成阅读`.
- Task draft helper: `提交后会保留为一次新的尝试记录`.
- Task success: `已提交，本次尝试已记录`.
- Quiz success: `已提交，系统已记录本次作答结果`.
- Feedback empty: `老师还没有留下反馈`.
- Feedback sent: `反馈已发送给学生`.

## Required screens and states

Phase 04 updates the static student/player surfaces into a data-backed learning
loop while keeping the Phase 01 visual language.

### Student dashboard

Route: `src/app/(student)/student/page.tsx` or the existing student dashboard
route.

The dashboard must show assigned or published lessons with a single most
relevant resume card. The top card uses a warm `surface-container-low` shell, a
white `surface-container-lowest` progress card, and a gradient primary CTA.

Required states:

- Has active lesson: show lesson title, course/class, progress fraction, and
  `继续学习`.
- Multiple lessons: show cards ordered by most relevant resume target first.
- No lessons: show the empty-state copy from this contract.
- Progress loading: use tonal `Skeleton` blocks, not spinners alone.
- Progress stale/error: show the error copy and a secondary `刷新状态` action.

### Lesson player

Route: `src/app/(student)/student/player/...` or equivalent lesson player route.

The player must use a cached lesson shell plus Suspense-streamed personal
regions:

1. Static/cached region: lesson title, objective, published step structure, and
   non-personal instructional content.
2. Streamed progress region: per-step state and resume position.
3. Streamed runtime region: teacher-forced active step placeholder for Phase 05.
4. Streamed submission region: latest task/quiz attempt and feedback status.

Layout contract:

- Desktop: two-column layout with a 260px to 300px step rail and a flexible
  learning canvas.
- Tablet/mobile: step rail becomes a horizontal rounded pill list above the
  canvas; content remains readable without side-by-side dependency.
- The current step is a white elevated card on a low surface; completed steps use
  success tonal containers; locked/forced steps use explicit text.

Required step states:

- `未开始` for untouched steps.
- `进行中` for the active step with pending progress.
- `已完成` for completed content/task/quiz steps.
- `已跳过` only when the server returns a permitted skipped state.
- `老师指定` when classroom runtime later forces the active step.

### Content step

Content steps must prioritize reading and completion confidence. The body uses
16px text at 1.5 line height in a white card nested inside a low surface. The
completion action label is `已完成阅读`. If the step has no body, show
`这个步骤暂时没有正文内容，请继续下一个步骤。`.

### Task step

Task steps must show the prompt, submission requirements, latest attempt, and
attempt history entry point. The input surface uses `surface-container-low`,
focuses to white with a 2px primary ghost outline, and has no 1px border.

Required task states:

- No attempt: show `还没有提交任务` and the task input.
- Draft typing: keep local client state only; authoritative submission state
  comes from Server Actions and DTOs.
- Submitting: disable the submit button and show `正在提交...`.
- Submitted: show `已提交，本次尝试已记录` and latest attempt timestamp.
- Attempt history: show attempts as rounded tonal cards labelled `第 1 次尝试`,
  `第 2 次尝试`, and so on.

### Quiz step

Quiz steps must support basic captured or scored outcomes. Each option is a
large rounded button or radio-like row with at least 44px height. Selected and
submitted states must include text labels.

Required quiz states:

- Unanswered: show question, options, and `提交答案`.
- Submitted captured: show `已记录你的答案`.
- Submitted scored: show `答对了` or `还可以再想想`, plus the captured score or
  outcome returned by the server.
- Retry permitted: show `再试一次` only if the DTO says another attempt is
  allowed.

### Teacher review and feedback

Route: teacher review surface inside the Phase 03 teacher workspace or a new
teacher lesson review route.

The teacher view must be a lightweight review cockpit, not a gradebook. Use
tonal summary cards for progress, latest submissions, attempt history, quiz
outcomes, feedback status, and a short feedback composer.

Required teacher states:

- Class overview: progress counts by `未开始`, `进行中`, and `已完成`.
- Student detail: latest task submission, attempt history, quiz outcome, and
  feedback status.
- No submissions: `这名学生还没有提交学习证据`.
- Feedback composer: label `给学生的简短反馈`, helper `最多 200 字，聚焦下一步改进`,
  CTA `发送反馈`.
- Feedback sent: `反馈已发送给学生`.

## Interaction and data boundaries

UI components must receive sanitized DTOs only. They must not import `src/db`,
schema tables, raw database clients, or unpublished draft lesson data.

Required interaction contracts:

- Dashboard resume reads must go through DAL DTOs scoped to the authenticated
  student and published lesson visibility.
- Student writes must call Zod-validated Server Actions for progress updates,
  task attempts, and quiz answers.
- Task and quiz submissions are append-only attempts. The UI must never present
  an edit-in-place or delete-last-submission flow.
- Latest submission cards read from the server-provided `isLatest` view or DTO;
  the client must not compute authoritative latest records from raw arrays.
- After progress, task, quiz, or feedback mutation, the action must update or
  invalidate the relevant progress/submission tags before the UI claims success.
- Classroom forced-step UI in Phase 04 is display-ready only. Live SSE behavior
  belongs to Phase 05, but the player must reserve the visible state label
  `老师指定`.

---

## Accessibility and responsive contract

Phase 04 is student-facing and must be comfortable on classroom laptops and
tablets.

- Every step rail item must be a button or link with a visible Chinese label.
- Current step, completed state, quiz outcome, and feedback status must have text
  labels in addition to color and icons.
- Form fields must have visible Chinese labels, not placeholder-only labels.
- Task textarea and quiz options must be keyboard reachable and preserve focus
  rings from `:focus-visible`.
- Mobile layouts must avoid horizontal overflow; the step rail can scroll
  horizontally with large rounded pills.
- Motion is optional and must be subtle. Do not animate answer correctness in a
  way that delays reading feedback.

---

## Anti-patterns

The executor must avoid these UI and interaction failures.

- No English-only labels, placeholder demo copy, or generic LMS table UI.
- No 1px divider lines, border-heavy cards, or black text/shadows.
- No raw database rows in props.
- No student access to draft lessons or draft steps.
- No mutable overwrite for task or quiz submissions.
- No full gradebook, weighted grades, rubric builder, SIS export, or bulk grading
  controls in this phase.
- No SSE live classroom dependency in Phase 04; only reserve visual states for
  Phase 05 runtime.
