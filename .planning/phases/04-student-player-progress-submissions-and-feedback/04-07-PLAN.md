<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| student session → cached shell DAL | Authenticated student identity and lesson access determine whether lesson shell data can be read and cached. |
| cached shell → personal streamed region | Cacheable published lesson data is combined with dynamic per-student progress/submission data at render time. |
| browser → Server Actions | Existing task, quiz, progress, and feedback mutations continue crossing through validated Server Actions; this plan must not bypass them. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-07-01 | I | `getStudentPlayerShellDTO` | mitigate | Keep `assertStudentCanAccessLesson()` in the cached shell loader before returning shell data, and keep unified `课时暂不可学习` errors per D-18 so unauthorized users cannot infer draft or permission details. |
| T-04-07-02 | I | `getStudentPlayerPersonalDTO` | mitigate | Do not add `'use cache'` to the personal loader; it must re-read the active student session and query progress/submission rows by current `studentId`. |
| T-04-07-03 | T | `src/app/(student)/student/player/page.tsx` | mitigate | Treat `searchParams.stepId` only as `selectedStepId`; DAL validates it against published shell steps and still prioritizes trusted `forcedStepId` when supplied. |
| T-04-07-04 | D | Suspense personal region | accept | Loading personal progress/submission separately may show a fallback during slow DB reads; fallback contains only non-sensitive Chinese loading copy and no fake state, so this is acceptable for ASVS L1. |
</threat_model>
