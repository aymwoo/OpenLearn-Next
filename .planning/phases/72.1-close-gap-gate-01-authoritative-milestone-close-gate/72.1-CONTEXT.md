# Phase 72.1: close-gap-gate-01-authoritative-milestone-close-gate - Context

**Gathered:** 2026-06-06
**Status:** Ready for planning

<domain>
## Phase Boundary

本 phase 是对 v4.0 milestone audit 暴露的 GATE-01 close gap 做收口：把当前偏“统一编排器”的 `verify:phase`，补强为真正可审计、可归档、可复用的 authoritative milestone close gate。

本 phase 只处理 close 证据层与 authoritative proof 层，不新增 v4.0 产品能力：
- 可以增强 Phase 71 / 72 的 proof strength，并补齐 70 / 71 / 72 的 phase-level verification artifacts。
- 必须继续复用既有 67 -> 71 verifier/proof lanes，不重写成第二套 milestone-only business kernel。
- `verify:phase` 继续保持唯一外部入口，依赖顺序继续固定为 67 -> 68 -> 69 -> 70 -> 71。
- 不重开 Phase 67-71 的功能 scope；这里只把 close gate 做成能直接支撑 v4.0 audit/archive 的 authoritative 交付面。

</domain>

<decisions>
## Implementation Decisions

### 权威性标准
- **D-72.1-01:** 72.1 必须新增一层更强的 milestone-level proof，不能只把现有证据重新排版成文档。
- **D-72.1-02:** 这层 stronger proof 必须同时证明两件事：一是 `verify:phase` 的 close 结论足够 authoritative；二是完整产品链已在 milestone 级入口下被重新收口，而不只是 phase verifier 顺序执行。
- **D-72.1-03:** 72.1 允许顺手加固当前最弱的 proof 层，特别是 Phase 71 / 72，而不是只靠解释现有 verifier 为什么“其实已经够强”。
- **D-72.1-04:** 本 phase 的目标终态是“v4.0 可直接进入 milestone archive”，而不是“只是多补一批 close 证据，后续再判断是否 authoritative”。

### 整链覆盖范围
- **D-72.1-05:** authoritative proof 必须覆盖完整六段链：声明/安装 -> teacher config -> student answer -> recap -> semver upgrade -> retain/cleanup uninstall。
- **D-72.1-06:** Phase 67 / 68 继续作为既有 verifier truth 复用，但在 72.1 的 verification / closeout 中必须被显式写入 proof chain，不能只是隐含前置条件。
- **D-72.1-07:** lifecycle 侧必须把 `upgrade`、`retain reinstall`、`cleanup uninstall` 三条治理路径都纳入 milestone authoritative proof，不能只选一个代表性分支。
- **D-72.1-08:** 课堂产品链与治理生命周期链都属于 non-negotiable 覆盖面；若实现成本上有取舍，不能牺牲其中任一侧。

### 证据产物形式
- **D-72.1-09:** 必须补齐 `.planning/phases/70-question-stats-post-class-recap/70-VERIFICATION.md`、`.planning/phases/71-marketplace-lifecycle-install-governance-semver-upgrade-reta/71-VERIFICATION.md`、`.planning/phases/72-end-to-end-verify-phase-close-gate/72-VERIFICATION.md`。
- **D-72.1-10:** 除 phase-level VERIFICATION 外，还必须新增一份 milestone-level closeout artifact，用来给 audit/archive 提供最终 close 结论、proof chain、delivered scope、explicit exclusions 与 deferred next steps。
- **D-72.1-11:** evidence 组织采用双入口：closeout 先给“能否归档”的结论与边界；verification/proof mapping 再给 requirement / flow / proof chain 的细证据入口。
- **D-72.1-12:** 70 / 71 / 72 的 VERIFICATION 都应尽量完整，不能写成只为填补空洞而存在的薄壳文档。

### 验证触达面
- **D-72.1-13:** authoritative proof 必须触达到真实 `UI + action/command + DAL/data truth` 三层，不能停留在 script/fixture/DAL-only 的自洽世界。
- **D-72.1-14:** `/settings/plugins` 必须在 72.1 的 stronger proof 中作为真实 lifecycle entry surface 出现，不能只间接引用底层 DAL 或 command proof。
- **D-72.1-15:** recap / stats 侧必须在 72.1 中被显式验证到真实 recap DTO 与 rendered recap surface，而不是只引用 Phase 70 的已有结果。
- **D-72.1-16:** 如果实现方式上需要在“更轻”与“更 authoritative”之间取舍，优先选择更重但更具权威性的 milestone proof。

### the agent's Discretion
- stronger proof 具体落在“增强 `scripts/verify-phase71-marketplace-lifecycle.ts` / `scripts/verify-phase72-close-gate.ts`”还是“新增少量 milestone-level focused proof helpers”，由 researcher / planner 决定；前提是不能退回 orchestration-only。
- milestone closeout 与 proof mapping 的具体文件命名、落点与拆分方式可由 planner 结合现有 repo 风格决定；前提是同时满足 close conclusion 和细证据双入口。
- UI touchpoint 的验证方式可在 Playwright、route/component focused tests、或混合方式中选择；前提是 `/settings/plugins` 与 recap surface 都要在 authoritative proof 中显式出现。
- phase VERIFICATION 文档与 milestone closeout 之间的内容复用方式可灵活处理，但每份文档都必须自洽，避免再次出现“代码通过但 audit 无法形式化验收”的情况。

</decisions>

### Established Patterns
- 仓库里 authoritative milestone close gate 的正确姿态，不是复制下游 verifier，而是复用下游 verifier 并追加 closeout-specific proof 与 artifact；`v2.2` Phase 38 是现成参考。
- phase 已通过代码和脚本验证并不等于 audit 可以 formal close；缺 `*-VERIFICATION.md` 会直接在 milestone audit 中被判成 partial / missing。
- audit 会区分“真实 broken flow”与“证明层不足”；72.1 当前已知主矛盾在 proof/verification artifact，而不是产品链已断。
- 对这类 close-gap，相比 DAL-only 或 fixture-only proof，repo 更偏好真实 product surface、server boundary、data truth 三层贯通的证据链。
- `verify:phase` 必须保持最新 milestone 的单一外部 gate；72.1 只能让它更 authoritative，不能把它拆成多个外部入口。

### Integration Points
- 规划/文档层：补写 70 / 71 / 72 phase-level `VERIFICATION.md`，并新增 72.1 所定义的 milestone closeout / proof mapping artifact。
- gate 层：增强 `scripts/verify-phase72-close-gate.ts`，必要时同步增强 `scripts/verify-phase71-marketplace-lifecycle.ts` 以支撑 stronger proof。
- lifecycle truth 层：围绕 `/settings/plugins` route、surface、actions、DAL/migration seam 建立 milestone-level authoritative evidence。
- recap truth 层：围绕 recap surface、DTO、cache invalidation、latest-only stats source 建立 milestone-level authoritative evidence。
- archive handoff 层：closeout artifact 必须能直接服务下一步 milestone audit/archive，而不是再次依赖作者口头解释。
