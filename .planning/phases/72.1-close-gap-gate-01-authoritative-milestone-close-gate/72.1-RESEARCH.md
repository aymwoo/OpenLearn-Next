**When to use:** 当 audit/archive 需要快速看 close 结论，同时又保留 requirement/flow 细证据入口时。[VERIFIED: `.planning/phases/72.1-close-gap-gate-01-authoritative-milestone-close-gate/72.1-CONTEXT.md`]
**Example:**
```markdown
## Close conclusion
## Delivered scope
## Proof chain summary
## Explicit exclusions
## Deferred next steps
```

### Pattern 4: Reuse phase truth, but write the proof chain explicitly
**What:** 67/68 可以继续作为 verifier truth，但在 72.1 closeout / verification 里必须被显式列为 proof chain，而不是默认大家“都知道它们是前置条件”。[VERIFIED: `.planning/phases/72.1-close-gap-gate-01-authoritative-milestone-close-gate/72.1-CONTEXT.md`]
**When to use:** 当 milestone authoritative proof 要覆盖完整六段链时。[VERIFIED: `.planning/phases/72.1-close-gap-gate-01-authoritative-milestone-close-gate/72.1-CONTEXT.md`]
**Example:**
```markdown
1. verify:phase67 — declaration / migration-proof truth
2. verify:phase68 — governed access truth
3. verify:phase69 — teacher config -> student answer truth
4. verify:phase70 — recap DTO + rendered recap truth
5. verify:phase71 — lifecycle truth
6. verify:phase72 — single external gate + milestone bridge proof
7. 72.1-CLOSEOUT.md — final archive conclusion
```

### Anti-Patterns to Avoid
- **把 72.1 做成纯文档重排：** 这直接违背 D-72.1-01，且 audit 已经说明“只会顺序跑 67-71”不足以满足 GATE-01 authoritative close。[VERIFIED: `.planning/phases/72.1-close-gap-gate-01-authoritative-milestone-close-gate/72.1-CONTEXT.md`; `.planning/v4.0-MILESTONE-AUDIT.md`]
- **新建第二套 milestone kernel：** 会分裂 single external gate，并违反“复用 67->71 verifier/proof lanes”的 locked decisions。[VERIFIED: `.planning/phases/72-end-to-end-verify-phase-close-gate/72-CONTEXT.md`; `.planning/phases/72.1-close-gap-gate-01-authoritative-milestone-close-gate/72.1-CONTEXT.md`]
- **只引用 DAL / fixture 证明而不触达 `/settings/plugins` 和 recap surface：** 这与 D-72.1-13/14/15 冲突。[VERIFIED: `.planning/phases/72.1-close-gap-gate-01-authoritative-milestone-close-gate/72.1-CONTEXT.md`]

## Common Pitfalls

### Pitfall 1: 把“Phase 72 已完成”误判成“milestone 已可归档”
**What goes wrong:** 看到 `pnpm verify:phase72` / `pnpm verify:phase` 已通过，就误以为 GATE-01 已 authoritative close。[VERIFIED: `.planning/STATE.md`; `.planning/v4.0-MILESTONE-AUDIT.md`]
**Why it happens:** Phase 72 的计划和 validation 都只定义了 aggregation + bookkeeping，并未要求新 business-level bridge proof。[VERIFIED: `.planning/phases/72-end-to-end-verify-phase-close-gate/72-01-PLAN.md`; `.planning/phases/72-end-to-end-verify-phase-close-gate/72-VALIDATION.md`]
**How to avoid:** 72.1 计划必须把 stronger proof、70/71/72 formal `VERIFICATION.md`、milestone closeout artifact 一起列为交付物。[VERIFIED: `.planning/phases/72.1-close-gap-gate-01-authoritative-milestone-close-gate/72.1-CONTEXT.md`]
**Warning signs:** close 结论仍然主要依赖 SUMMARY frontmatter、脚本 wiring、或作者口头解释。[VERIFIED: `.planning/v4.0-MILESTONE-AUDIT.md`]

### Pitfall 2: 误把“Phase 71 code review 已 resolved”当成“milestone-level lifecycle proof 已足够”
**What goes wrong:** 因为 71 的 code review 已收敛，就忽略了 milestone audit 对 71/72 证明强度的更高要求。[VERIFIED: `.planning/phases/71-marketplace-lifecycle-install-governance-semver-upgrade-reta/71-REVIEW.md`; `.planning/v4.0-MILESTONE-AUDIT.md`]
**Why it happens:** code review 证明“代码问题已修复”，但不自动等于“phase verification / milestone close artifact 已形式化收口”。[VERIFIED: `.planning/phases/71-marketplace-lifecycle-install-governance-semver-upgrade-reta/71-REVIEW.md`; `.planning/v4.0-MILESTONE-AUDIT.md`]
**How to avoid:** 把 71 的 resolved code path 视为输入 truth，再用 72.1 补 formal `71-VERIFICATION.md` 和 stronger milestone proof，而不是重复修代码或跳过文档层。[VERIFIED: `.planning/v4.0-MILESTONE-AUDIT.md`; `.planning/phases/72.1-close-gap-gate-01-authoritative-milestone-close-gate/72.1-CONTEXT.md`]
**Warning signs:** 计划里只有“补 audit 文案”或只有“跑一次 `verify:phase71`”而没有 formal verification artifact。[VERIFIED: `.planning/v4.0-MILESTONE-AUDIT.md`]

### Pitfall 3: proof chain 没把 67/68 显式写出来
**What goes wrong:** closeout 看起来覆盖了 install→recap→lifecycle，但 declaration/migration-proof 和 governed access truth 只被当作隐含前置条件。[VERIFIED: `.planning/phases/72.1-close-gap-gate-01-authoritative-milestone-close-gate/72.1-CONTEXT.md`]
**Why it happens:** 67/68 没有新增 UI surface，容易在 milestone narrative 中被省略。[VERIFIED: `.planning/ROADMAP.md`; `.planning/REQUIREMENTS.md`]
**How to avoid:** 在 closeout 和 proof mapping 中把 `verify:phase67` / `verify:phase68` 作为 proof chain 前两环显式列出。[VERIFIED: `.planning/phases/72.1-close-gap-gate-01-authoritative-milestone-close-gate/72.1-CONTEXT.md`]
**Warning signs:** 72.1 closeout 只从 69 或 70 开始讲故事。[VERIFIED: locked decision D-72.1-06 in CONTEXT]

### Pitfall 4: stronger proof 只停留在 script/fixture 世界
**What goes wrong:** planner 只增强 isolated SQLite proof 或静态 grep，而没有触达 `/settings/plugins` 与 recap rendered surface。[VERIFIED: `.planning/phases/72.1-close-gap-gate-01-authoritative-milestone-close-gate/72.1-CONTEXT.md`]
**Why it happens:** repo 已有大量 verifier seam，最容易的路径就是继续堆 script-level assertions。[VERIFIED: `scripts/verify-phase71-marketplace-lifecycle.ts`; `scripts/verify-phase72-close-gate.ts`]
**How to avoid:** 至少为 `/settings/plugins` 和 recap surface 各保留一个真实 surface-level proof 入口，并在 `VERIFICATION.md` 中把 UI→action→DAL 链写全。[VERIFIED: `src/app/settings/plugins/page.tsx`; `src/components/classroom/classroom-session-recap-surface.tsx`; `.planning/phases/72.1-close-gap-gate-01-authoritative-milestone-close-gate/72.1-CONTEXT.md`]
**Warning signs:** `72-VERIFICATION.md` 里只出现 script 名、命令名、或 DAL helper 名，而没有 surface path / component / DTO 证据。[VERIFIED: audit gap description + current file inventory]

### Pitfall 5: 引入 Playwright 但忘了 repo 里没有现成 config
**What goes wrong:** planner 直接把 Playwright 设成默认路径，结果 Wave 0 先花时间搭配置和基建，而不是先关主缺口。[VERIFIED: glob `playwright.config.*`; `package.json`]
**Why it happens:** Playwright 已安装，容易误判为“浏览器 proof 零成本”。[VERIFIED: `package.json`; shell `pnpm exec playwright --version`]
**How to avoid:** 默认走 existing Vitest + verifier hybrid；只有当 planner 明确需要一条浏览器 smoke 时，才把 Playwright 作为补充 proof，而不是基础设施前置任务。[VERIFIED: `vitest.config.mts`; `.planning/phases/71-marketplace-lifecycle-install-governance-semver-upgrade-reta/71-VALIDATION.md`] 
**Warning signs:** 第一个 plan wave 主要在搭 Playwright config，而不是补 `VERIFICATION.md` / stronger proof / closeout artifact。[VERIFIED: current repo has no config and phase goal is urgent close gap]
