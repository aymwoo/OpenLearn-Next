<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP Request → Upload Route | 不可信 multipart 数据进入——路径穿越防护 + 配额检查 + SHA-256 验证 |
| HTTP Request → Download Route | 不可信 fileId query param——DAL 强制施加 schoolId+pluginId 双重隔离 |
| HTTP Request → Delete/List/Metadata Routes | 不可信 fileId/prefix——DAL/facade 层强制施加权限隔离 |
| API Route → 文件系统 | 所有文件系统操作经过 sanitizeFilePath + buildStoragePath（绝对路径在 FILE_STORAGE_ROOT 内） |
| API Route → Command Bus | upload 仅传元数据（Binary Bypass 不变式） |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-80-15 | Tampering | upload multipart parsing | mitigate | 文件名经过 sanitizeFilePath 四层消毒；SHA-256 在服务端独立计算（不信任客户端提供的 hash）；流式管道在 error 时 fs.unlink 清理部分文件 |
| T-80-16 | Tampering | upload 幂等竞态 | mitigate | fs.createWriteStream(path, { flags: "wx" }) 独占创建；EEXIST → 检查已存在文件 SHA-256 匹配；不匹配时清理 + 返回 409（冲突）|
| T-80-17 | Denial of Service | upload QuotaTransform | mitigate | QuotaTransform 在超过 maxBytes 时立即中断流；pipeline 的 error handler 清理部分写入文件；单文件 50MB + 总计 500MB/插件/校 双重上限 |
| T-80-18 | Elevation | download fileId injection | mitigate | getFileRecord 强制执行 schoolId+pluginId 双重 where 条件；diskPath 由 resolveStoragePath 在 FILE_STORAGE_ROOT 下解析——即使 fileId 被伪造也无法访问其他插件/学校的文件 |
| T-80-19 | Elevation | delete fileId cross-plugin | mitigate | dispatchSystemCommand facade 调用 assertActionExecutable → schoolId 从 session 派生；handler execute 的 softDeleteFile 施加 schoolId+pluginId 双重检查 |
| T-80-20 | Information Disclosure | download Content-Disposition | mitigate | 始终设置 Content-Disposition: attachment（触发下载，不内联渲染）；Cache-Control: private, no-cache（防止代理缓存） |
| T-80-21 | Information Disclosure | metadata MIME sniffing | mitigate | Content-Type 使用 DB 记录的 mimeType（上传时从 multipart Content-Type 头提取），不进行文件内容嗅探 |
| T-80-SC | Tampering | npm/pip/cargo installs | mitigate | 无新包安装——仅使用 Node.js 内置模块和已有的项目依赖 |
</threat_model>
