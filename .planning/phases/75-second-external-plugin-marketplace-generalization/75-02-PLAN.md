<objective>
构建 homework 插件的 authoring + student runtime 层：教师在 lesson step editor 中创建 homework 步骤，学生在 classroom player 中查看作业并提交。定义 homework 的 DAL 层（dispatchPluginDataAccess facade 消费）和 Server Actions（auth split 鉴权）。此 plan 为 Plan 03 的教师批改面板提供数据基础。

Purpose: 把 authoring + student runtime 链路跑通，Plan 03 的 grading panel 才能拿到真实提交数据。
Output: 教师可创建 homework 步骤并发布 lesson，学生可在课堂中提交作业，quiz 回归全绿。
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| homework Server Actions → DAL → SQLite | 写路径经 dispatchPluginDataAccess facade + Command Bus，append-only/isLatest 事务 |
| student submit payload → Zod DTO | DTO 边界 strictObject 校验，拒额外字段 |
| auth split → Server Actions | 教师/学生角色在 auth.ts 中校验，越权提交被拦截 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-75-05 | Tampering | 学生提交 payload | mitigate | HomeworkSubmissionDTOSchema.strictObject() 在 DAL 入口校验 |
| T-75-06 | Elevation | 学生越权创建作业 | mitigate | createHomeworkAssignmentAction 检查 session.role==="teacher" |
| T-75-07 | Information Disclosure | 学生查看他人提交 | mitigate | getHomeworkSubmissions 按 classroomSession + student 范围过滤 |
| T-75-08 | Repudiation | 提交操作审计 | mitigate | dispatchPluginDataAccess 走 governanceAudit 表记录 |
| T-75-09 | XSS | 作业描述富文本渲染 | mitigate | MarkdownRenderer sanitize 输出，禁止 raw HTML |
</threat_model>
