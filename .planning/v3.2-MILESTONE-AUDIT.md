# Milestone v3.2 Audit — AI LessonAgent 起草闭环

**Status:** ⚠ gaps_found
**Audited:** 2026-06-01

## Verdict

All five phases (61–65) are individually complete: 22/22 plans have SUMMARY.md, Phase 62 and Phase 65 have explicit passing VERIFICATION.md, and the authoritative `verify:phase` close gate ran live and PASSED (14 static boundary checks + `npm run build` + Phase 61–65 regression = 18 files / 145 tests green).

**However, the milestone does not connect into its advertised end-to-end loop.** Independent cross-phase wiring inspection found two BLOCKER seams at the same orchestration boundary, both confirmed by direct source grep:

1. **No teacher-facing trigger** calls `draftLessonStep` (the `lesson.draft.run` producer) — only the test does.
2. **`lesson.draft.persist` is never dispatched** — nothing bridges a successful run to persistence, so no AI draft ever reaches the `draftLessonVersions` table through the chain. This starves the entire review/accept/discard surface (Phase 64).

Additionally, accept/discard server actions reach the DAL by **bypassing the Command Bus**, leaving the `lesson.draft.accept/discard` commands and their provenance events orphaned, and exposing a latent `version: 0` event-schema violation.

The `verify:phase` gate passed because it validates per-phase static boundaries + unit/contract tests — it does not assert that a production **producer** exists for `lesson.draft.run` / `lesson.draft.persist`, nor that accept/discard route through the bus. Those are exactly the inter-phase seams that fail here.

## Recommended Closure (single phase, one orchestration seam)

The gaps are concentrated at one seam, so one closure phase can resolve them:

1. **Bridge run → persist:** after a successful `lesson.draft.run`, dispatch `lesson.draft.persist` (a producer in the agent orchestration path) so the generated step package reaches `draftLessonVersions`.
2. **Add a teacher trigger:** a server action / route + UI control that invokes `draftLessonStep` for a target lesson (respecting `lesson_agent_enabled`).
3. **Route accept/discard through the Command Bus:** replace direct DAL calls in `applyDraftLessonVersionAction` / `discardDraftLessonVersionAction` with `dispatchPlatformCommand('lesson.draft.accept'|'discard')`, and fix the `version: 0` event payload (resolve real version from DAL result).
4. **Reconcile** the stale REQUIREMENTS.md traceability table.
